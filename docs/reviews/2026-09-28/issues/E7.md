## Summary

`add-to-steam.py:100-111` finds the next shortcut index with `re.findall(rb'\x00(\d+)\x00', data)` and takes `matches[-1]`. Entry keys are `\x00<idx>\x00`, but the same byte shape occurs for any digit-only *string value* (an appname `2048`, `LaunchOptions` `1`) and for any `T_INT` whose low byte is `0x30–0x39` followed by `0x00`; and "last match in file order" is not "max key". `remove-from-steam.py` was written precisely because "a byte-splice that guesses wrong does not fail loudly, it silently corrupts the file" (its header L7-18) — its inverse still guesses. ARCHITECTURE §1 says the two are a pair.

## Evidence

```python
def get_latest_index(data):
    matches = re.findall(rb'\x00(\d+)\x00', data)
    if matches:
        return int(matches[-1])
    return -1
```

Measured on pristine with a two-entry fixture (key 5 = appname `2048` with `LaunchOptions` `1`, then key 0 = RetroArch, last in file order): the new entry gets key **1** (keys after the run: `5 0 1`; correct is 6). With appname `2048` as the last entry the regex returns `['1', '2048']` → next index 2049.

## Failure scenario

Existing library: entry 0 "RetroArch", entry 1 "2048" (last) → new index 2049 (Steam tolerates gaps, but the remover's renumbering later hides the evidence). Or entry 1 has `LaunchOptions "1"` and an index 2 already exists → the new entry is written with key 2 too → duplicate key; Steam drops or merges one of them — the user's or ours.

## Suggested fix

Use the remover's parser (a verbatim copy with a `# PAIRED WITH` comment — the two scripts are downloaded and run standalone by the installer/uninstaller, so a shared `mcss_vdf.py` would break the `fetch_url` fallback), take `max(int(key)) + 1`, and refuse to splice into a file that does not round-trip:
