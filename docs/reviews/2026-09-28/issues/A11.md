## Summary
ARCHITECTURE §2: "ALL state-file reads go through [instance_lifecycle's] accessors — no raw jq elsewhere" (PRINCIPLES #1/#9). `modules/orchestrator.sh` still runs `jq … "$state"` directly on `.slots`/`.mode` in four places: `_get_mode` (`:166-169`), `_find_slot_by_event_node` (`:246-253`, used at `:599`), `_find_slot_by_uniq` (`:266-275`, NO production caller — only `tests/test_controller_monitor.sh:1075`), `_collect_mask_pairs` (`:287-296`); plus `_find_free_slot` (`:226-234`, used at `:564`) duplicates `slot_find_free`. The jq bodies are byte-for-byte parallels of `modules/slot_manager.sh:104-133`, whose header states "PR-c retires the orchestrator's near-duplicate `_find_free_slot` / `_find_slot_by_uniq` / `_find_slot_by_event_node`" (`:43-48`) — PR-c shipped, the retirement did not; the same header still says the module is "DARK ON ARRIVAL … ZERO runtime callers" (`:15-19`), false since PR-c. Found independently as A11 and B2.

## Evidence

`grep -rn '_find_slot_by_uniq' --include='*.sh'` → definition + one test only.

## Failure scenario
Schema drift: `slot_free` now nulls `phys_*`/`disconnected*` fields that `_collect_mask_pairs`/`_find_slot_by_*` know nothing about; any future field rename (or a change to how `active` is represented) is a two-place edit that silently breaks `CONTROLLER_REMOVE` resolution on the legacy path while the proxy path keeps working — invisible to the tests, which stub `_collect_mask_pairs`.

## Suggested fix
Delete the three duplicates; route the legacy `CONTROLLER_ADD` and the `CONTROLLER_REMOVE` resolution through `slot_find_free` / `slot_find_by_event_node`; add a `get_mode` accessor next to `get_active_slots`; move `_collect_mask_pairs` (a `.slots` schema read) into instance_lifecycle, name unchanged so the two existing test stubs keep working; retire T2.21 (`tests/test_slot_manager.sh` already covers `slot_find_by_uniq`); fix the stale slot_manager/runtime_context headers. `_set_mode` stays as-is: it is the designated single WRITER and holds the flock.
