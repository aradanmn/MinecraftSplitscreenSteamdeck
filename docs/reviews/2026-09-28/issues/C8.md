severity: medium

## Summary
`download_prism_launcher` (`modules/launcher_setup.sh:60-97`) skips the download whenever `-f "$TARGET_DIR/PolyMC.AppImage"` is true (`:62`) and fetches with a raw `wget -O` (`:94`) — no `fetch_url`, no timeout, no size or magic check of the ~30 MB binary that will be executed. `wget -O` creates the target before transferring, so a drop mid-way (or `set -e` aborting because `wget` is absent on a curl-only box) leaves a 0-byte/partial `PolyMC.AppImage` that every subsequent run reports as "already present". `get_prism_executable` later returns that broken file and PolyMC "fails to start" with nothing pointing at the cause.

## Evidence
```bash
# launcher_setup.sh:62 — -f, not -s / ELF
if [[ -f "$TARGET_DIR/PolyMC.AppImage" ]]; then
    print_success "PolyMC AppImage already present"
...
# :94-95 — the only raw wget left in the installer modules; no fetch_url, no timeout
wget -O "$TARGET_DIR/PolyMC.AppImage" "$prism_url"
chmod +x "$TARGET_DIR/PolyMC.AppImage"
```
Reproduced with a 0-byte pre-existing file and with a stubbed download that writes `<html>404` and fails:
```
== ORIGINAL
[FAIL] T7.23a rc=0 size=0            (0-byte file accepted as "already present")
[FAIL] T7.23b rc=0 left: PolyMC.AppImage   (partial download kept, function "succeeded")
== PATCHED
[PASS] T7.23a a 0-byte AppImage is re-downloaded (and lands executable)
[PASS] T7.23b partial/non-ELF download: exit 1, nothing left behind
[PASS] T7.23c no staging leftover
```

## Failure scenario
Wi-Fi drops at 40% during the very first installer step → partial AppImage → installer aborts. The user re-runs: "✅ PolyMC AppImage already present", the install completes, and the Steam shortcut fails with a FUSE/exec error from a truncated file. The only cure is knowing to delete the file by hand.

## Suggested fix
```diff
--- a/modules/launcher_setup.sh
+++ b/modules/launcher_setup.sh
@@ -49,6 +49,12 @@

+# _mcss_is_elf: does $1 start with the ELF magic (\x7fELF)? The cheapest
+# "this is a real binary, not a 0-byte/HTML/partial download" check (C8).
+_mcss_is_elf() {
+    [[ -s "$1" && "$(head -c4 "$1" 2>/dev/null)" == $'\x7fELF' ]]
+}
+

+    # satisfied by the 0-byte/partial file a failed `wget -O` left behind,
+    # so every later run said "already present" and PolyMC never started.

         print_success "PolyMC AppImage already present"

+    elif [[ -e "$TARGET_DIR/PolyMC.AppImage" ]]; then

     fi

+    # C8: download to a temp file beside the target (fetch_url, timeout 0 —
+    # a ~30 MB bulk artifact), validate the ELF magic, then mv into place.
+    # The raw `wget -O` created the target before transferring, so a drop
+    # at 40% left a partial AppImage that satisfied the "already present"
+    # check forever; on a curl-only box the missing wget aborted under set -e.
+    local staged
+    staged=$(mktemp "$TARGET_DIR/.PolyMC.AppImage.XXXXXX") || exit 1

+        print_error "PolyMC AppImage download failed or is not an ELF binary."
+        print_error "  URL: $prism_url"
```

The skip is now gated on "non-empty and starts with `\x7fELF`" — every AppImage is an ELF, so a 0-byte, HTML-error-page or truncated-at-the-header file is re-fetched with a warning. The download goes through the one transport (`fetch_url`, timeout 0 as for every bulk artifact) into a `mktemp` file next to the target and is only renamed into place after the same ELF check, so a failure leaves nothing behind (STYLE-GUIDE §7.9). The `exit 1` matches the function's existing contract. Deliberately not changed: the `PolyMC/PolyMC` GitHub source (the launcher abstraction is tracked in IMPROVEMENTS-ANALYSIS-2026-08-15) and the lack of a full digest check — a truncation in the middle of a 30 MB file still passes the magic check; the fuller fix is to read the release asset's `digest` field from the same GitHub API response already fetched (`.assets[].digest`, `sha256:<hex>`, published for new uploads since 2025) and verify with `sha256sum` before the `mv`, falling back to the magic check when the field is absent. Note the progress bar is gone (`fetch_url` is `-sS`); a `print_info` line announces the fetch, and `run_with_spinner` can wrap it if the silent ~30 MB wait proves confusing on the Deck.

Verification done: (a) `bash -n`; (b) `git apply --check` from the repo root; (c) `tests/test_installer.sh` 17/17 on a scratch clone with the patched file; the fixture test below is green on the patch and red on the original.

## Tests
Add `test_t7_23` to `tests/test_installer.sh`: stub `fetch_url` so that `-` (the GitHub API call) prints a one-asset JSON and a file target runs a per-case body; (a) with a pre-existing 0-byte `$TARGET_DIR/PolyMC.AppImage` and a download body that writes `\x7fELF…` → function returns 0, file starts with the ELF magic and is executable; (b) with no file and a body that writes `<html>404` and returns 18 → exit 1 and `PolyMC.AppImage` does not exist; (c) no `.PolyMC.AppImage.*` leftovers.

Mutation (PRINCIPLES #4): change `_mcss_is_elf` back to `[[ -f … ]]` in the skip → (a) red; drop `|| ! _mcss_is_elf "$staged"` → (b) red. Confirmed in this session.
