## Summary
`slot_claim` step 1 (`modules/slot_manager.sh:209-221`): a known `uniq` on an active slot that is NOT flagged disconnected returns `REJECT` with no mutation, regardless of whether the incoming `$ev` equals the stored `event_node`. A pad that re-enumerates without a processed `CONTROLLER_REMOVE` (USB autosuspend, driver reset, a remove lost during a burst, or REMOVE arriving after ADD on a fast flap) therefore keeps the OLD node in state; the proxy keeps following a stale symlink and a later real REMOVE (looked up by the NEW node) matches nothing, so the slot is never marked disconnected and can never be resumed/adopted.

## Evidence
`modules/slot_manager.sh:211-220`:
```bash
slot=$(slot_find_by_uniq "$uniq" | head -n 1)   # newest/first; multi only on clones
if [[ -n "$slot" ]]; then
    if slot_is_disconnected "$slot"; then
        slot_touch "$slot" "$ev"
        printf 'RESUME %s\n' "$slot"
        return 0
    fi
    # Already active+connected — a duplicate/echo add. No-op.
    printf 'REJECT\n'
    return 0
fi
```
The pre-existing "no udev remove" defect is disclosed in `orchestrator.sh:578-590`'s comment, but that note covers the flag-off path only. Reproduced with the new matrix test against the pristine module: `slot_claim A … /dev/input/event9` on a slot storing `event7` -> `REJECT`, `event_node` still `event7`.

## Failure scenario
Pad on slot 2 was `/dev/input/event7`; it re-appears as `event9` with no REMOVE processed. `slot_claim` -> `REJECT`. evsieve keeps waiting on the `slot2` symlink -> `event7` (persist=reopen). If the kernel later reuses `event7` for a different pad, slot 2's sandbox is driven by the wrong player; if not, slot 2 is input-dead. The eventual REMOVE of `event9` finds no slot, so slot 2 never becomes disconnected/abandoned and only a window-gone `SLOT_DIED` can ever free it.

## Suggested fix
In step 1 compare `$ev` with the stored `event_node`; if it differs, `slot_touch` + `RESUME` (the orchestrator's RESUME path already calls `proxy_repoint_slot`, which re-links the pads symlink and confirms the evsieve is live). Keep `REJECT` for the exact-echo case only.

Mutation: pristine `slot_manager.sh` + the new test -> red (`REJECT`, `event7`), observed.

Why correct: the decision is still identity-first (known MAC -> its slot), the only new outcome is for a state the old matrix could not express (connected + different node). `proxy_repoint_slot` is idempotent (`ln -sfn` + liveness check) so a RESUME on a live slot is harmless. Deliberately NOT changed: the disconnected -> RESUME branch, the grace/adopt policy, and the flag-off path (`slot_claim` is only reached with the proxy on).
