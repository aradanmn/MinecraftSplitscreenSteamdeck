## Summary
`get_supported_minecraft_versions` decides which versions to OFFER via `check_mod_version_compatibility`, which calls the shared ladders with the weaker guard: `match_modrinth_version … 0` (no standalone-major.minor check, `modules/version_management.sh:223-224`) and `match_curseforge_version … "1"` (fallback never gated on patch safety, `:274-278`). The later scan that actually INSTALLS (`check_modrinth_mod`, `modules/mod_management.sh:401`, `… 1`; `check_curseforge_mod`, `:494-515`, guarded) uses the strong guard. Where the two differ, a version is listed as "All required mods compatible" and the scan then reports the required mod as incompatible; instance creation prints "CRITICAL … continuing" and the game ships without it. This is `[KNOWN: docs/TODO.md:33-35]` — #88 deliberately preserved the "three pre-existing divergences by parameter" and documented each site; this issue is the follow-up that comment anticipates, because the consequence is user-visible.

## Failure scenario
A required mod publishes a `1.21`-only build; the user is offered 1.21.3 ("✅ 1.21.3 - All required mods compatible"), picks it, and the scan says "❌ Sodium - no compatible Fabric version for Minecraft 1.21.3"; the install proceeds with the required performance mod missing and only a CRITICAL line in the middle of the log.

## Suggested fix
Adopt the strong policy at both sites: pass `check_standalone=1` for Modrinth, and move the CurseForge patch-safety guard out of `check_curseforge_mod` into one helper that both sites call (PRINCIPLES #9 — not a second copy of the guard).

This is a behaviour change on purpose (the strong guard now also filters the menu), so it must land as its own change with the TODO.md:33-35 note updated. `check_curseforge_mod`'s own result is byte-identical (the guard code moved, not changed). The `strict_mode` path, the ladder tiers, `get_curseforge_download_url` (which #88 documents as a genuinely different sequential ladder) and the third divergence #88 records are untouched. Note the review's observation that with `check_standalone=1` the bare `$mc_major_minor` tier of `match_modrinth_version` can never succeed (a standalone `1.21` release is exactly what blocks the fallback): it becomes dead in both paths after this change, and can be deleted in a later cleanup once the two sites are proven to agree on hardware. If a maintainer prefers the weak policy everywhere instead, the same diff with `1 → 0` at `mod_management.sh:401` and `_curseforge_fallback_allowed` returning "1" is the alternative; either way the two sites must share one parameter.
