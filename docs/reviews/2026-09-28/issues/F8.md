severity: medium

## Summary
`system/deck-display-fixes/deck-display-resume.sh:14-20` fires `resume-display-restore.service` on every `post` resume, and the worker `resume-display-restore.sh:52-60` does `if [ "$external" -eq 1 ]; then … restart_gamescope`, where `external` means only "some `card0-DP-*` connector reports `connected`". There is no check that the external output is actually broken — no EDID test, no `enabled`/`dpms` read, no `is-active` failure. `systemctl --user restart gamescope-session.target` tears down Steam and every game under it. PRINCIPLES #5 says a false positive must not kill a running player's session; here there is not even a detector — the restart is the default.

## Evidence
```bash
# resume-display-restore.sh:47-60
external=0
for status_file in /sys/class/drm/card0/card0-DP-*/status; do
    [ -f "$status_file" ] || continue
    [ "$(cat "$status_file" 2>/dev/null)" = "connected" ] && external=1
done

if [ "$external" -eq 1 ]; then
    log "external display connected -> restarting gamescope to re-drive output"
    restart_gamescope
```

## Failure scenario
Four players mid-game, Deck docked. The Deck auto-suspends on an idle/power event, or someone taps the power button and resumes → the hook fires, the worker sees `connected`, restarts the session → all four Minecraft instances, the nested KWin and the supervisor die; the same "session torn down under the player" class as #135, from a script rather than the orchestrator.

## Suggested fix
Only restart when a failure is observed. After the existing 8 s settle, read what the kernel says about every connected DP output — `edid` size, `enabled`, `dpms` — and treat "no EDID, or not enabled, or DPMS not On" as broken. Log the observed values on every resume so the maintainer can see what a real failure looks like. Keep the env-sanitize step unconditional (harmless). Keep an escape hatch `RESUME_RESTORE_FORCE=1` that restores the old always-restart behaviour while the detector is validated on hardware.

Why this is correct: when gamescope is driving the dock, the DP connector is `enabled` with `dpms=On` and carries an EDID; the two failure modes this worker exists for (stale `WAYLAND_DISPLAY` crash-loop, MST probe not re-done after thaw) leave the output `disabled`, `Off`, or EDID-less. The `is-active` fallback still restarts a session that died. Exercised locally against fake sysfs trees (dry-run): healthy → "driven -> no action"; EDID 0 B / `disabled` / `dpms=Off` → restart; healthy + `RESUME_RESTORE_FORCE=1` → restart. Deliberately NOT changed: the 8 s settle, `sanitize_env`, the undocked branch, the log file location (F12), and the hard-coded UID (F11). Design note (PRINCIPLES #2): the new detector is on by default rather than dark-first because the current default is the destructive action; a wrong "healthy" verdict costs a re-dock or a manual restart, a wrong "restart" costs everyone's game — fail-open (#5) argues for the new default, and `RESUME_RESTORE_FORCE=1` is the one-line rollback.

Validation done: (a) `bash -n` and `shellcheck -S warning` clean; (b) `git apply --check` succeeds from the pristine repo root; (c) no unit suite covers `system/`; the decision table was exercised with a sed-redirected copy of the script against four fake `/sys/class/drm` trees in `RESUME_RESTORE_DRYRUN=1` mode (log excerpts in the "why" paragraph).

## Tests
Add `tests/test_resume_display_restore.sh` (CI-safe): make the sysfs root overridable (`DRM_ROOT="${DRM_ROOT:-/sys/class/drm/card0}"` — a one-line follow-up to the diff) and stub `systemctl`; cases: (1) healthy connected output → log contains `no action`, no `would: … restart`; (2) EDID empty → `would: systemctl --user restart`; (3) `enabled=disabled` → restart; (4) `dpms=Off` → restart; (5) no DP connected, session active → `no action`; (6) healthy + `RESUME_RESTORE_FORCE=1` → restart. Mutation (PRINCIPLES #4): drop the `broken` check (restore `if [ "$external" -eq 1 ]; then restart`) → case 1 goes red; invert `[ "$edid_size" -eq 0 ]` → case 2 red. Cases 1-4 and 6 were run by hand as described above.

## Hardware verification
Game Mode, docked (official dock + monitor), 4 pads, `cd system/deck-display-fixes && ./install.sh` from Desktop Mode first. Launch Minecraft Splitscreen 4-up, all players in-world. Press the power button to suspend, wait 15 s, resume. Observe: all four instances still running and responsive; `cat /tmp/resume-display-restore.log` (journal after F12) shows `card0-DP-N: connected edid=…B enabled=enabled dpms=On` and `external display connected and driven -> no action`; `grep -c teardown ~/.local/share/PolyMC/splitscreen-debug-latest.log` unchanged before/after. Negative case: undock, suspend, resume → `no external display, session healthy -> no action`. If the original black-screen-after-resume bug reproduces on this Deck, capture the log line's `edid/enabled/dpms` values — they are the detector's inputs — and, if the detector missed it, set `RESUME_RESTORE_FORCE=1` in the unit's `Environment=` as the interim rollback and file the values. Relevant harness: `tests/hardware/stage3_hotplug.sh` (docked flow) and `stage6_teardown.sh` (proves the session was not torn down by anything but the operator).
