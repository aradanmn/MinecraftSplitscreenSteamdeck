severity: medium

## Summary
`spawn_instance` backgrounds two keeper subshells without redirecting their fds: the title-keeper (`modules/instance_lifecycle.sh:1114-1121`, 15 x 1 s) and the map-keeper (`:1149-1161`, 45 x 2 s, with a bare `echo … >&2` at `:1156`). In `handheld_flow` the spawn is synchronous through a pipe (`modules/orchestrator.sh:754`: `spawn_instance 1 "" "" 2>&1 | sed … >&2`), and a pipeline only completes when every writer closes — i.e. when the map-keeper exits, ~90 s later. The FIFO event loop does not start until then. The docked `_launch_slot` mktemp-failure fallback (`orchestrator.sh:460`) has the same shape; in its normal branch the keepers write into a temp log that is `sed`'d and unlinked as soon as `spawn_instance` returns, so their diagnostics are lost. Merged finding: E27.

## Evidence
`modules/instance_lifecycle.sh:1114-1121` / `:1149-1161`:
```bash
( _k=0; while (( _k < INSTANCE_LIFECYCLE_TITLE_REASSERT_COUNT )); do … sleep …; done ) &
…
( _m=0; while (( _m < INSTANCE_LIFECYCLE_MAP_KEEP_COUNT )); do … echo "[spawn_instance] map-keeper: …" >&2; sleep …; done ) &
```
`modules/orchestrator.sh:754`:
```bash
spawn_instance 1 "" "" 2>&1 | sed 's/^/[orchestrator] /' >&2 || true
```
Reproduced with T4.22 below against the pristine module: after `spawn_instance` returns with its stdout on a capture pipe, both keeper subshells still hold `pipe:[…]` as fd 1 (`children=3 … holding a pipe=2`).

## Failure scenario
Handheld launch: the window appears; for the next ~90 s `_reap_dead_slots`, `_check_monitor_heartbeats`, `SLOT_DIED` and `DISPLAY_MODE_CHANGE` (the user docks during loading — the #134 class) are not processed. If the game crashes in that window the player stares at a black screen until the keeper loop times out.

## Suggested fix
Redirect both keepers off the caller's fds (PRINCIPLES #8): `</dev/null >>"${LOG:-/dev/null}" 2>&1 &`. Their diagnostics now land in the session log instead of a pipe or a deleted temp file.

Verification done: (a) `bash -n` passes; (b) `git apply --check` succeeds from the repo root against the pristine tree; (c) `tests/test_instance_lifecycle.sh` 17/17 with T4.22 in a patched scratch clone (`tests/test_slot_manager.sh`, `test_watchdog.sh`, `test_reconnect_dispatch.sh` unaffected). Why correct: the keepers only call `dex_*` (stderr already discarded) and `sleep`; nothing consumed their stdout. `$LOG` is the same file `setsid bash -c "$bwrap_command"` on `:1077` already appends to, so this is the established convention two lines away. Deliberately NOT changed: keeper counts/intervals, and tracking the keeper PIDs for `cleanup()` (B24 in the low/info batch — record them in a module array so `cleanup()` can signal them; they are bounded and harmless meanwhile).

## Tests
`tests/test_instance_lifecycle.sh` T4.22 (TEST_TOTAL 16 -> 17). Runs `spawn_instance` with mock bwrap and stubbed `dex_*`/poll functions while its stdout is a `$( )` capture pipe, then inspects `/proc/<child>/fd/1` of every child subshell it left behind and kills them (our own PIDs):
```bash
test_t4_22() {
    local tmpdir; tmpdir=$(mktemp -d); trap 'rm -rf "$tmpdir"' RETURN
    local state_file="$tmpdir/splitscreen_state.json"

{"mode":"docked","slots":{"1":{"active":false},"2":{"active":false},"3":{"active":false},"4":{"active":false}}}
JSON
    local mock_bin="$tmpdir/mock_bin"; mkdir -p "$mock_bin"

    printf '#!/bin/bash\nexit 0\n' > "$tmpdir/PolyMC.AppImage"; chmod +x "$tmpdir/PolyMC.AppImage"
    local fds
    fds=$(
        export SPLITSCREEN_STATE="$state_file" MCSS_LAUNCHER_ROOT="$tmpdir" MCSS_GEOM_DIR="$tmpdir/geom"
        export BWRAP_CMD="$mock_bin/bwrap" MCSS_LAUNCHER_EXEC="$tmpdir/PolyMC.AppImage" PATH="$mock_bin:$PATH"

        _poll_for_java()      { echo ""; }
        _poll_for_window()    { echo 12345; }
        dex_set_name()        { :; }
        dex_set_decorations() { :; }
        dex_is_viewable()     { echo viewable; }
        dex_map_raise()       { :; }
        sync_apply_layout()   { :; }

        spawn_instance 2 /dev/input/event4 /dev/input/js1 2>"$tmpdir/spawn.err" || true

    n_pipes=$(grep -c 'pipe:' <<< "$fds" || true)

        _pass "T4.22 — keeper subshells are redirected off the capture pipe (B9)"
```

Mutation: remove the redirect from either keeper -> that keeper's fd 1 reads `pipe:[…]` -> red.

## Hardware verification
Game Mode handheld (stage2_handheld), then dock during loading (stage3 / #134 path). Launch handheld; within 5 s of `[spawn_instance] Stored WID … for slot 1` the log must show the event loop alive — e.g. `[orchestrator] Watchdog PID` followed by heartbeat/reap lines, and docking the Deck 10 s after the window appears must produce `DISPLAY_MODE_CHANGE → docked` in `/tmp/splitscreen-debug-latest.log` within one poll, not ~90 s later. `grep 'map-keeper' /tmp/splitscreen-debug-latest.log` now shows the keeper diagnostics (previously lost in the docked path). Crash test: `kill -9 <java pid>` 20 s after launch -> `SLOT_DIED 1` within the watchdog interval, not after the keeper timeout.
