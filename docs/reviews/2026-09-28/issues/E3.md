## Summary

`_reflow_layout` (`modules/orchestrator.sh:334-341`) does `if ! sync_apply_layout …; then _REFLOW_NEEDED=1; return 1; fi` and its H10 comment promises that a reflow failure is surfaced so the event loop retries it. But `apply_layout` (`modules/window_manager.sh:285-397`) has no explicit return: its exit status is that of its trailing `if [[ "${WINDOW_MANAGER_REASSERT…}" == "1" && … ]]` block, which is 0 whether the condition was false or the body's `echo` ran. Because the call sits inside `if !`, errexit is suppressed for the whole chain (that is also why E2's abort does not happen on THIS path), so `_position_slot`'s `return 1` is simply discarded. `_REFLOW_NEEDED` can never become 1. This issue builds on [E2] (which introduces the `_failed` bookkeeping); apply E2 first.

## Evidence

Pristine, empirically: with `_position_slot() { return 1; }` stubbed, `if ! apply_layout "1 2" 1280 800; then echo "returned nonzero"; else echo "returned 0 despite _position_slot failing"; fi` prints the latter. The function's last statement:

```bash
    if [[ "${WINDOW_MANAGER_REASSERT:-${MCSS_REASSERT:-1}}" == "1" && ${#_positioned[@]} -gt 0 ]]; then
        …
        echo "[window_manager] re-asserted ${#_positioned[@]} (re)positioned slot(s)" >&2
    fi
}
```

`modules/orchestrator.sh:334-341` (the consumer that can never fire):

```bash
    if ! sync_apply_layout "$active" "$ruleW" "$ruleH"; then
        echo "[orchestrator] WARNING: reflow (sync_apply_layout) failed for slots: $active" >&2
        _REFLOW_NEEDED=1
        return 1
    fi
    _REFLOW_NEEDED=0
```

## Failure scenario

Dock/undock → `DISPLAY_MODE_CHANGE` → `_reflow_layout` → KWin unreachable during the mode switch, every `_position_slot` fails → `apply_layout` returns 0 → `_REFLOW_NEEDED=0` → no retry on the next FIFO iteration; the windows stay tiled for the old output until an unrelated reflow trigger. The retry that H10 "implemented" cannot fire — the same family of symptoms as #134/#79 (mode transition leaves the layout wrong).

`apply_layout` now returns 1 iff at least one `_position_slot` call failed (the `_failed` array E2 fills), 0 otherwise, and the contract is documented in the module Public API, the function header and `sync_apply_layout` (STYLE-GUIDE §2). Conservative on purpose: a slot that failed the first pass but succeeded on the re-assert still counts as failed — the orchestrator's retry is cache-guarded (E2 removes the cache entry only for failed slots), so confirming costs one skipped reposition, never a flicker. The only caller outside `if !` — `spawn_instance` step 8 — gets an explicit `|| echo WARNING` so the new non-zero status cannot errexit a foreground caller; the map-keeper and the orchestrator's post-spawn `_reflow_layout` (which now really retries) remain the recovery path. Nothing in the orchestrator changes: its H10 code is finally reachable as written.

## Tests

Add next to E2's T3.10 (`tests/test_window_manager.sh`):

```bash
# T3.11 (E3) — apply_layout's status is real: 1 when any slot failed, 0 when all placed.
test_t3_11() {
    _run_layout() {   # $1 = _position_slot body, $2 = active slots
        bash -c 'set -euo pipefail; export MCSS_MAX_PLAYERS=4; source "$1"
            MCSS_GEOM_DIR=$(mktemp -d); export MCSS_GEOM_DIR
            _get_wid_from_state() { echo ""; }
            eval "_position_slot() { $2; }"
            WINDOW_MANAGER_REASSERT=0 apply_layout "$3" 1280 800' _ \
            "$REPO_ROOT/modules/window_manager.sh" "$1" "$2" >/dev/null 2>&1
    }
    local rc_fail=0 rc_ok=0
    _run_layout 'return 1' "1 2" || rc_fail=$?
    _run_layout 'return 0' "1 2" || rc_ok=$?
    if (( rc_fail == 1 && rc_ok == 0 )); then
        _pass "T3.11 — apply_layout returns 1 on failure, 0 on success"
    else
        _fail "T3.11" "rc on failure=$rc_fail (want 1), rc on success=$rc_ok (want 0)"
    fi
}
```

Mutation (PRINCIPLES #4): replace the new `return 1` with `:` → T3.11 red (`rc on failure=0`). Note T3.11 alone is not a discriminator against *pristine* (there the subprocess dies with status 1 from errexit), which is why T3.10 (E2) must accompany it.

## Hardware verification

Game Mode docked, 2 pads, then undock to handheld (stage3_hotplug + the #134/#79 transition checks):

1. Launch 2-up docked; undock (or pull HDMI) so `DISPLAY_MODE_CHANGE` fires while KWin is re-outputting.
2. `grep -E "reflow \(sync_apply_layout\) failed|positioning failed for slot|_REFLOW_NEEDED|Applying layout" ~/.local/share/PolyMC/splitscreen-debug-latest.log`: after the fix a failed reflow shows the WARNING pair and is followed, within one `ORCHESTRATOR_FIFO_READ_TIMEOUT_S` cadence, by another `Applying layout:` line for the same slots (the retry). Before the fix only the first `Applying layout` appears and the tiles stay in the old geometry.
3. Steady-state check: on a healthy reflow no WARNING lines appear and `apply_layout`'s `skip reposition (no flicker)` lines still appear for unchanged tiles (return 0 path).
