## Summary
`fetch_url`/`fetch_url_status` (`modules/utilities.sh:84-132`) have no header support, so every authenticated CurseForge call re-implements transport with its own `curl`/`wget` pair and its own (or no) timeout: `modules/mod_management.sh:476` (`timeout 15`), `:828` (none), `:976`, `:993`, `:1014` (none), `:1135` (none), `:1232` (none), `:1455` (`-m 12`), `:1547` (`-m 15`), `:1676` (none); `modules/version_management.sh:254` (none); plus the unauthenticated `modules/launcher_setup.sh:94` (`wget -O`, none — covered by C8). This is exactly the drift #51 D14 removed for the unauthenticated sites, reproduced for the authenticated ones. `version_management.sh:254` runs inside the 20-version scan, so one stalled TCP connection hangs the installer forever with no spinner and no countdown (PRINCIPLES #6). The `-H "x-api-key: $key"` argv form also exposes the key in `/proc/<pid>/cmdline` on every call (C14).

## Evidence
```bash
# version_management.sh:254 — inside the per-version scan; no --max-time at all
http_code=$(curl -s -L -w "%{http_code}" -o "$tmp_body" -H "x-api-key: $cf_api_key" "$cf_api_url")

# mod_management.sh:976-978 — one of five curl/wget pairs with no timeout
curl -s -H "x-api-key: $api_token" -o "$temp_file" "$api_url" 2>/dev/null
wget -q --header="x-api-key: $api_token" -O "$temp_file" "$api_url" 2>/dev/null
```
`grep -n 'curl\|wget' modules/mod_management.sh modules/version_management.sh | grep -v '^\s*#'` lists the eleven sites above; only three carry any bound, and those three disagree (12/15/`timeout 15`).

## Failure scenario
Any CurseForge mod in `mods.conf` or a custom CurseForge mod, plus a stalled connection (captive portal, half-open TCP after a Wi-Fi roam): the installer sits at "Testing 1.21.x..." indefinitely. Ctrl-C is the only way out, and the trap-swallowing issue (F4) makes even that unreliable.

## Suggested fix
Extend the one transport with an optional header FILE (`curl -H @file`; wget `--header=` per line), add the single API timeout constant, expose a 0600 header-file accessor next to the token accessor, and route the sites through it. The diff below is the `utilities.sh` extension plus ONE representative call-site conversion (the scan-path site at `version_management.sh:254`, the most damaging one).

The extension is backward compatible: `$3`/`$4` are optional and every existing caller keeps its exact behaviour (`${3:-…}` still resolves an omitted or empty timeout to the default 15). The header-file form keeps the key out of argv (curl reads `@file` itself; the wget branch expands lines into `--header=` arguments, which is the same exposure as before for that fallback only). `-L` is kept for parity with the existing transport — dropping it for API calls (C14, redirect header forwarding) is a one-line follow-up once all sites are converted. The header file is created once per process under `umask 077`; the installer's existing `cleanup` trap does not remove it, so add `rm -f "${_MCSS_CF_HDR_FILE:-}"` there when landing (one line in `install-minecraft-splitscreen.sh:82-87`).

Remaining sites to convert, same pattern (`hdr=$(mcss_cf_header_file) || return 1`, then `fetch_url "$url" "$file" "" "$hdr"` or `fetch_url_status …`, deleting the `command -v curl/wget` branches):
- `mod_management.sh:476` `check_curseforge_mod` — replace `timeout 15 curl …` + the `curl_exit -eq 124` branch (a `000` status now means timeout/transport failure).
- `mod_management.sh:828` `resolve_curseforge_dependencies` — dead code (C16); delete rather than convert.
- `mod_management.sh:976`, `:993`, `:1014` `resolve_curseforge_dependencies_api` — three calls; see C17 for collapsing to one.
