## Summary
`_ensure_state_file` (`modules/instance_lifecycle.sh:151-165`) discards the previous session's state — including its recorded `bwrap_pid`/`pid` — without attempting to reap them, so a crashed session's game trees are simply forgotten. `_poll_for_java` (`:628`) then matches ANY process whose cmdline contains `instances/latestUpdate-N/natives` and takes the first match (`head -1` = lowest pid = OLDEST process), and `_collect_slot_pids` (`:652`) roots the window search on every match. Combined, the next session binds the new slot to the previous session's leaked JVM and window.

## Evidence
`modules/instance_lifecycle.sh:151-165` ("Always reset — stale state from a previous crashed session poisons the next" — but the pids in it are never signalled), and `:628`:
```bash
found_pid=$(pgrep -af "$search_pattern" 2>/dev/null | head -1 | awk '{print $1}' || true)
```
`:652`:
```bash
roots=$(pgrep -f "$search_pattern" 2>/dev/null || true)
```
Each step confirmed in code; the combined scenario needs a prior crash or a B1 orphan.

## Failure scenario
Session A crashes (or B1 leaks slot 2's JVM). Session B spawns slot 2: `_poll_for_java` returns the OLD JVM's pid before the new one starts; `_poll_for_window` (`dex_search --pid` over the old subtree) may store the OLD window's WID; `apply_layout` positions the stale window; when the old JVM finally exits the watchdog fires `SLOT_DIED 2` for the NEW instance; `teardown_instance` group-kills only the new bwrap's group — the old JVM survives again, and `pgrep | head -1` picks it again on the next spawn.

## Suggested fix
Two parts. (1) Before the reset, `_reap_recorded_slot_pids` reads each slot's recorded `bwrap_pid`/`pid` through the accessors, identity-verifies each against `/proc/<pid>/cmdline` (the cmdline must name this slot's instance: `-l latestUpdate-2` on the setsid'd launcher, `instances/latestUpdate-2/natives` on the JVM — the same rule `controller_proxy.sh:_proxy_pid_is_ours` uses), then SIGTERM -> bounded grace -> SIGKILL the group. Recorded pids only, never a name match (PRINCIPLES #7). Every `_ensure_state_file` caller (`minecraftSplitscreen.sh:585,830,879`, `_set_mode`'s missing-file init) is a session-start path, so nothing reaped can be a live instance of this session. (2) `_poll_for_java` / `_collect_slot_pids` only accept matches that descend from the slot's tracked `bwrap_pid` (`/proc` ppid walk); an empty leader passes everything through unchanged (fail open, PRINCIPLES #5).

Mutations (all observed red): drop the `_reap_recorded_slot_pids` call -> T4.21 `ours_alive=1`; replace the identity check with `true` -> T4.21 `theirs_alive=0` (a recycled pid would have been killed); disable the descendant filter -> T4.20 keeps `$$`.

Why correct: reaping is limited to pids WE recorded and verified — a recycled pid whose cmdline does not name the slot is logged and left alone. The descendant filter is a strict subset of the old global match, so nothing new is ever selected; with no leader (mock mode, or a `bwrap_pid` write that failed) the old behaviour is retained. Deliberately NOT changed: `_ensure_state_file`'s "always reset" policy, the poll timings, and the `teardown_instance` kill sequence (B1 handles that).
