## Summary

The Python backend generated by `modules/dex.sh` declares `XWindowAttributes` with `colormap` as the *last* field, but `Xlib.h` puts `Colormap colormap` between `save_under` and `map_installed` (`/usr/include/X11/Xlib.h:325-328`). The struct's total size still matches (136 bytes on x86_64), so nothing overflows — every field after `save_under` is simply read from the wrong offset: `map_state` at byte 80 (the low half of the colormap XID) instead of byte 92. `action_is_viewable` (`modules/dex.sh:448-458`) therefore prints "viewable" only when a window's colormap XID happens to be 2, and `dex_is_viewable` — the probe the Fix #57 map-keeper polls every 2 s (`modules/instance_lifecycle.sh:1148-1160`) — effectively always answers "unmapped".

## Evidence

`modules/dex.sh:102-117` (pristine):

```python
        ('save_under', Bool), ('map_installed', Bool),
        ('map_state', ctypes.c_int),
        ('all_event_masks', ctypes.c_ulong), ('your_event_masks', ctypes.c_ulong),
        ('do_not_propagate_mask', ctypes.c_ulong),
        ('override_redirect', Bool), ('screen', ctypes.c_void_p),
        ('colormap', ctypes.c_ulong),
```

`Xlib.h` (checked on this host):

```c
    Bool save_under;		/* boolean, should bits under be saved? */
    Colormap colormap;		/* color map to be associated with window */
    Bool map_installed;		/* boolean, is color map currently installed*/
    int map_state;		/* IsUnmapped, IsUnviewable, IsViewable */
    long all_event_masks;
    long your_event_mask;
    long do_not_propagate_mask;
    Bool override_redirect;
    Screen *screen;
} XWindowAttributes;
```

Offsets measured (C `offsetof` via a 6-line program compiled against the system header, and `ctypes` on the struct extracted from the heredoc):

| field | C (Xlib.h) | dex pristine | dex patched |
|---|---|---|---|
| colormap | 80 | 128 | 80 |
| map_installed | 88 | 76 | 88 |
| map_state | **92** | **80** | 92 |
| override_redirect | 120 | 112 | 120 |
| screen | 128 | 120 | 128 |
| sizeof | 136 | 136 | 136 |

`modules/dex.sh:457`: `print("viewable" if a.map_state == 2 else "unmapped")` — with `map_state` reading the colormap XID this is "viewable" only for colormap 2.

## Failure scenario

Every spawn, in every mode: step 9 of `spawn_instance` starts the map-keeper, which calls `dex_is_viewable "$window_id"` up to `INSTANCE_LIFECYCLE_MAP_KEEP_COUNT` (45) times at 2 s intervals. It always gets "unmapped", so it runs `dex_map_raise` (XMapWindow + XRaiseWindow) 45 times per slot and logs `map-keeper: re-mapped unmapped window` 45 times, whether or not the game ever unmapped anything. With four slots, four keepers raise their windows against each other for the first 90 s of play. The "only re-show when the game really unmapped it" design is not what runs, and any future consumer of `dex_is_viewable` (a watchdog "is the tile visible?" probe, for instance) is misled the same way. `override_redirect` is also misread (112 vs 120) but nothing reads it back today.

The reorder makes the declaration match `Xlib.h` field for field (`your_event_masks` was also a typo for `your_event_mask`; the three masks are `long` in the header, so `c_long` — same size, sign only). Geometry (`x, y, width, height`) precedes the error and was always correct, so `dex_getgeometry`/`_verify_window_geometry` behaviour does not change. Nothing else in the backend or its callers changes; the map-keeper's polling loop is untouched — it just starts receiving true answers.

Verification done on a scratch copy: (a) `bash -n modules/dex.sh` and `python3 -m py_compile` on the backend extracted from the patched heredoc — both pass; (b) `git apply --check` of the diff above from the repo root against the pristine tree — succeeds; (c) no `tests/test_dex*.sh` suite exists; the new offset test below was run against pristine (red: `map_state` 80), patched (green) and a field-swap mutation (red) — see Tests.

## Tests

Add `tests/test_dex_struct.py` (no X display needed — it extracts the `DEXPYEOF` heredoc and evals only the type/struct block):

```python
#!/usr/bin/env python3
"""tests/test_dex_struct.py — E1 guard: dex's XWindowAttributes must match Xlib.h.
Usage: python3 tests/test_dex_struct.py [modules/dex.sh]"""
import ctypes, re, sys
path = sys.argv[1] if len(sys.argv) > 1 else "modules/dex.sh"
src = open(path).read()
body = src.split("<< 'DEXPYEOF'\n", 1)[1].split("\nDEXPYEOF\n", 1)[0]
m = re.search(r"Atom = ctypes.c_ulong\n.*?class XWindowAttributes\(ctypes.Structure\):\n"
              r"    _fields_ = \[\n.*?\n    \]\n", body, re.S)
ns = {"ctypes": ctypes}; exec(m.group(0), ns)
X = ns["XWindowAttributes"]
expect = {"map_state": 92, "colormap": 80, "map_installed": 88,
          "override_redirect": 120, "screen": 128}
if ctypes.sizeof(ctypes.c_long) != 8:
    print("SKIP: offsets pinned for LP64 (x86_64) only"); sys.exit(0)
bad = {f: getattr(X, f).offset for f, o in expect.items() if getattr(X, f).offset != o}
if ctypes.sizeof(X) != 136: bad["sizeof"] = ctypes.sizeof(X)
if bad:
    print(f"[FAIL] XWindowAttributes layout drifted from Xlib.h: {bad}"); sys.exit(1)
print("[PASS] XWindowAttributes matches Xlib.h (map_state@92, sizeof 136)")
```

Results: pristine → `[FAIL] … {'map_state': 80, 'colormap': 128, 'map_installed': 76, 'override_redirect': 112, 'screen': 120}`; patched → `[PASS]`. Mutation (PRINCIPLES #4): swapping `map_installed` and `map_state` in the patched struct → `[FAIL] … {'map_state': 88, 'map_installed': 92}`. Wire it into CI next to the bash suites (`python3 tests/test_dex_struct.py`).
