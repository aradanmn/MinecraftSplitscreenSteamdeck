## Summary
`launchFromPlasma`'s STARTUP GUARD (`minecraftSplitscreen.sh:439-460`) reaps leftovers with three name-matched `pkill -9 -f` patterns. The third one, `pkill -9 -f "$_launcher_name"` (`minecraftSplitscreen.sh:447`), is the bare basename of `MCSS_LAUNCHER_ROOT` (`PolyMC`), and the launcher is deployed *inside* that root (`install-minecraft-splitscreen.sh:334` → `$HOME/.local/share/PolyMC/minecraftSplitscreen.sh`, run by Steam as `…/PolyMC/minecraftSplitscreen.sh launchFromPlasma`, `add-to-steam.py:131-133`). `pkill -f` matches the full cmdline and excludes only its own PID, so whenever the guard fires it SIGKILLs the supervisor mid-sweep (and Steam's `reaper … -- …/PolyMC/minecraftSplitscreen.sh …`). `|| true` cannot help against SIGKILL. Reproduced in the sandbox (see Tests). PRINCIPLES #7.

## Evidence
```bash
# minecraftSplitscreen.sh:435-447
local _launcher_name
_launcher_name=$(basename "$MCSS_LAUNCHER_ROOT")        # "PolyMC"
…
if [[ -n "$_stale_tree" ]] || [[ -n "$(_mcss_nested_pids 'startplasma-wayland')" ]] || pgrep -f "$MCSS_INSTANCE_PREFIX" >/dev/null 2>&1; then
    …
    for _g in 1 2 3; do
        pkill -9 -f "$MCSS_INSTANCE_PREFIX" 2>/dev/null || true
        pkill -9 -f "bwrap.*$_launcher_name" 2>/dev/null || true
        pkill -9 -f "$_launcher_name" 2>/dev/null || true       # <-- matches OUR OWN cmdline
```
Reproduction (sandbox): a script at `/tmp/x/PolyMC/t.sh` running `pkill -9 -f PolyMC` never reaches its next line. The test below reproduces it against the real `launchFromPlasma` (child bash reported `Killed`, the SURVIVED marker never written).

## Failure scenario
Any launch that finds leftovers — a stale nested session after a gamescope reset, a leftover `latestUpdate-` JVM, a stale `prodFromPlasma` tree — makes the guard fire: the first two pkills kill the instances, the third kills *this* supervisor. The rest of the guard (`_mcss_nested_pids` kills, `rm -rf "$MCSS_GEOM_DIR"`, the `systemctl --user stop 'app-MinecraftSplitscreen@*'`) and the launch itself never run; Steam sees the "game" exit and bounces to the library. Second launch (guard skipped, nothing left) works — the "first launch after leftovers bounces, second works" symptom the #58 comment attributes solely to errexit. It also SIGKILLs any unrelated process whose cmdline contains `PolyMC` (a Desktop-Mode PolyMC, an AppImage extraction).

## Suggested fix
Delete the bare-name pattern. The two scoped patterns already cover the whole instance tree: the bwrap leader matches `bwrap.*<root>`; PolyMC's `AppRun`/AppImage is invoked with `-l "${MCSS_INSTANCE_PREFIX}${slot}"` (`modules/instance_lifecycle.sh:391,600`) and the JVM carries `instances/latestUpdate-N/natives` in `-Djava.library.path` (which is exactly what `_poll_for_java` greps for, `instance_lifecycle.sh:621`), so both match `$MCSS_INSTANCE_PREFIX`.

Why this is correct: the third pattern was strictly a superset of the second for the instance tree (every bwrap→PolyMC→java process either contains `bwrap.*PolyMC` or `latestUpdate-`), so removing it drops only the self-match and the collateral matches. It deliberately does NOT change the `-9`, the three-pass loop, or the still-unscoped instance patterns (#58 accepted those as unambiguous). **Fuller fix (design decision):** kill only PIDs the previous run recorded — the state file's `bwrap_pid`/`pid` per slot plus the `_mcss_nested_pids` marker set (PRINCIPLES #7); that needs A8 first, because today the outer supervisor is not marked.

Checks done: (a) `bash -n` on the patched file — OK; (b) `git apply --check` against the pristine tree — OK; (c) `tests/test_orchestrator.sh` (sources the launcher) on the patched tree — 9/9; the new T6.10 below is red on the original (`Killed`) and green on the patched file.

## Tests
Add `T6.10` to `tests/test_orchestrator.sh` (bump `TEST_TOTAL`). It runs `launchFromPlasma` in a child bash whose *own* `$0` carries the launcher-root basename (exactly like the deployed path), forces the guard with a throwaway `sleep` whose cmdline carries `MCSS_INSTANCE_PREFIX`, and asserts the child survives. Mutation that must turn it red (PRINCIPLES #4): re-add `pkill -9 -f "$_launcher_name"` — verified: the original file fails it.

```bash
#!/bin/bash
# T6.10 — launchFromPlasma's STARTUP GUARD must not SIGKILL the launcher itself
# (A1). Runs launchFromPlasma inside a child bash whose OWN cmdline ($0) carries
# the launcher-root basename, exactly like the deployed
# ~/.local/share/PolyMC/minecraftSplitscreen.sh does. The guard is forced to
# fire via a throwaway `sleep` whose cmdline carries MCSS_INSTANCE_PREFIX.
# A self-kill means the SURVIVED marker is never written.
LAUNCHER="$1"
tmpdir=$(mktemp -d); trap 'rm -rf "$tmpdir"' EXIT
unset SPLITSCREEN_DEBUG_LOG   # keep this test tree UNMARKED for _mcss_nested_pids
name="mcssA1probe$$"
export MCSS_LAUNCHER_ROOT="$tmpdir/$name"; mkdir -p "$MCSS_LAUNCHER_ROOT/instances"
export MCSS_INSTANCE_PREFIX="mcssA1inst$$-"
export MCSS_GEOM_DIR="$tmpdir/geom"
export MCSS_AUTOSTART_DIR="$tmpdir/autostart"
# leftover "instance": its cmdline carries the instance prefix → guard fires
cp "$(command -v sleep)" "$tmpdir/${MCSS_INSTANCE_PREFIX}1"; "$tmpdir/${MCSS_INSTANCE_PREFIX}1" 60 & lf=$!
bash -c '
  source "$LAUNCHER" >/dev/null 2>&1
  mcss_require_gamescope() { return 0; }
  _start_nested_plasma() { _NESTED_SESSION_PID=""; }   # no nested session
  _supervise_reap_nested_session() { return 0; }
  _restore_session_env() { return 0; }
  launchFromPlasma
  echo SURVIVED > "$OUT"
' "$name" 2>/dev/null
kill "$lf" 2>/dev/null; wait "$lf" 2>/dev/null
if [[ "$(cat "$OUT" 2>/dev/null)" == SURVIVED ]]; then echo "[PASS] T6.10 — startup guard does not kill the launcher"; exit 0
else echo "[FAIL] T6.10 — launcher process died inside the startup guard (self pkill)"; exit 1; fi
```

## Hardware verification
Game Mode, docked or handheld, 1 pad. (1) Deploy, launch once, quit — baseline. (2) Create leftovers: launch, then from SSH `kill -9 $(pgrep -f 'minecraftSplitscreen.sh prodFromPlasma')` and Stop the game from Steam (leaves a nested session/JVM behind — same shape as a gamescope reset). (3) Launch again from the Steam library. Expect the game to come up on the FIRST try. Proof: `grep -E 'STARTUP GUARD|boot phase ended' /tmp/splitscreen-debug-latest.log` shows `leftover nested session/instances found`, `reap done`, and then `nested session boot phase ended` — before the fix the log ends at the "found" line and Steam returns to the library. `tests/hardware/run_all.sh stage6` (teardown exit matrix, marked-survivor assertions) and RUNBOOK-HW2 Part 1 (orchestrator smoke) apply.
