## Summary
When `$MCSS_RUNTIME_DIR/mcss` cannot be created or written, `mcss_resolve_paths` falls back to `export MCSS_HELPER_DIR="/tmp"` (`modules/runtime_context.sh:343-349`). The launcher then writes the KWin shim to `$MCSS_KWIN_WRAPPER_PATH` = `/tmp/kwin_wayland_wrapper` (follows a pre-planted symlink) and does `export PATH="$MCSS_HELPER_DIR:$PATH"` → `PATH=/tmp:…` (`minecraftSplitscreen.sh:274-277`): EVERY command lookup in this process and all its children (`jq`, `python3`, `bwrap`, `kwin_wayland`, `pkill`, …) resolves in world-writable `/tmp` first. The comment says "N6/N7 hardening degraded"; the PATH prepend is a full local-user hijack. Same class, same root: `dex.sh:66` executes `/tmp/dex_backend_$UID.py` with `python3` when `XDG_RUNTIME_DIR` is unset and a foreign file there aborts the launcher at source time (`mv -f` refused by the sticky bit, `:516`, unguarded call `:522` under `set -e`) — E14; `controller_proxy.sh:379-392` `mkdir -p`s the symlink farms and `>>`-opens `evsieve-slot<N>.log` under the same fallback, accepting a pre-existing foreign dir/symlink silently — D16.

## Failure scenario
Multi-user host (or CI/container) where `/run/user/$UID` is absent: another local user drops `/tmp/jq` (or `/tmp/kwin_wayland_wrapper`, `/tmp/dex_backend_1000.py`, a symlink at `/tmp/proxy-pads`) → executed as the Deck user by the launcher, or the launcher aborts at module load. Status: PLAUSIBLE on a stock Deck (needs the fallback), CONFIRMED mechanism.

## Suggested fix
Fall back to a PRIVATE dir: a stable per-user `${TMPDIR:-/tmp}/mcss-$UID` (created 0700, refused if pre-existing as a symlink or not ours — stable so the outer supervisor and the re-exec'd inner handler still share it), else `mktemp -d`; keep bare `/tmp` only as the last resort. Add `mcss_dir_is_private` and make the launcher skip BOTH the shim write and the PATH prepend unless the dir is private (fail open: nested KWin at default size). dex: home the backend under `MCSS_HELPER_DIR` and never abort the sourcing shell. controller_proxy: refuse a pads/virt/helper dir that is a symlink or not owned by us.

Why this is correct: the normal Deck path (`/run/user/1000/mcss`, 0700) is untouched — the only behavioral change on a stock Deck is dex's backend moving from `$XDG_RUNTIME_DIR/` into `$MCSS_HELPER_DIR/` (same tmpfs, and `cleanup()` already removes `$DEX_PY_SCRIPT`). `mcss_exec_env_string` does not carry `MCSS_HELPER_DIR`, so the fallback is deliberately deterministic per user first (both processes resolve the same dir) and random only when that name is unusable. It deliberately does NOT move the FIFO (A13), the geom cache (E15) or the debug log (A21) — same class, separate diffs.
