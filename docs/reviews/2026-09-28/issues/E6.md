## Summary

`_dex_run` (`modules/dex.sh:531-535`) is `DEX_DISPLAY=… python3 "$DEX_PY_SCRIPT" "$@"` — no `timeout`, no `signal.alarm` (the backend imports `signal` at `:91` and never uses it). `modules/window_manager.sh:312-314` justifies never using xdotool because it "can block indefinitely inside gamescope's XWayland, freezing the synchronous caller" — but dex makes the same blocking Xlib calls via ctypes (`XSync` after every step of `action_move_resize_remap`, `:383-408`; one round-trip `XGetWindowProperty` per window in the recursive tree walk), so it inherits the same hang mode. `apply_layout`, `_reflow_layout`, `_poll_for_window` (every 0.5 s), the title-keeper, the map-keeper and the watchdog's `_check_slot_window` all sit on it. PRINCIPLES #6.

## Evidence

`modules/dex.sh:531-535` (pristine):

```bash
_dex_run() {
    [[ -f "$DEX_PY_SCRIPT" ]] || _dex_generate_backend
    DEX_DISPLAY="${DEX_DISPLAY:-${MCSS_DISPLAY:-${DISPLAY:-:0}}}" python3 "$DEX_PY_SCRIPT" "$@"
}
```

Reproduced with a stand-in backend that blocks (`python3` on PATH replaced by `exec sleep 30`) and `DEX_TIMEOUT_S=1`: pristine `dex_is_viewable 1` never returns (killed by a 12 s outer guard); patched returns after 1 s. Alarm path alone (no `timeout` binary — the backend's imports+alarm prologue followed by a blocking C `sleep(30)` via ctypes): process dies with SIGALRM (rc -14) after 2 s, i.e. the alarm fires even inside a C call, where a Python-level exception could not.

## Failure scenario

XWayland stalls (a gamescope reset mid-reflow — the "gamescope reset" `kwin_positioner.sh:217` documents): `dex_list_windows` in `apply_layout` blocks forever → `_reflow_layout` never returns → the FIFO event loop is stuck (PRINCIPLES #10: one handler at a time) → no further `CONTROLLER_ADD`/`REMOVE`/`SLOT_DIED` processing; the watchdog's `_check_slot_window` hangs on the same call. From the outside this is a wedged session that cannot be torn down cleanly (#135 territory).

Two independent bounds: `timeout --foreground "$DEX_TIMEOUT_S"` in the shell (coreutils, present on SteamOS and CI; exit 124 is just another non-zero status — every caller already does `|| true`, `|| echo gone` or `|| echo ""`), and `signal.alarm(DEX_TIMEOUT_S + 1)` in the backend as a second line of defence (SIGALRM's default disposition kills the interpreter even while blocked in a C Xlib call). `DEX_TIMEOUT_S` is a named, guarded, env-overridable module constant (`_S` suffix per ARCHITECTURE §3) and is exported because a `VAR=val cmd` prefix on a readonly variable is refused by bash — the #184 lesson. 5 s is generous: a healthy dex call completes in tens of milliseconds. Deliberately not changed: an `XSetIOErrorHandler` — Xlib's default IO-error handler already exits the process when the connection dies; the hang this fixes is a live connection that never replies. The `_dex_cleanup`/`DEX_PY_SCRIPT` path questions are E14 (folded into A12/D16).

Verification done on a scratch copy: (a) `bash -n modules/dex.sh` and `python3 -m py_compile` on the backend extracted from the patched heredoc pass; `source`-ing the module twice in one shell works (constants guard); (b) `git apply --check` from the repo root against the pristine tree succeeds, and cumulatively after [E1] (different hunks of the same file); (c) no unit suite covers dex.sh; the two timing probes above were run on pristine and patched.

## Tests

Add to a new `tests/test_dex.sh` (no display needed):

```bash
# T-E6.1 — a hung backend is bounded: _dex_run returns within DEX_TIMEOUT_S (+1s slack).
test_e6_1() {
    local fake; fake=$(mktemp -d); printf '#!/bin/bash\nexec sleep 30\n' > "$fake/python3"; chmod +x "$fake/python3"
    local t0=$SECONDS rc=0
    timeout 10 bash -c 'export DEX_TIMEOUT_S=1 DEX_PY_SCRIPT=$(mktemp) PATH="$2:$PATH"
        source "$1"; dex_is_viewable 1' _ "$REPO_ROOT/modules/dex.sh" "$fake" >/dev/null 2>&1 || rc=$?
    if (( rc == 124 && SECONDS - t0 <= 3 )); then     # 124 = timeout's own status, not the outer guard's (that is also 124 but at >=10s)
        _pass "T-E6.1 hung dex backend bounded at DEX_TIMEOUT_S ($((SECONDS - t0))s)"
    else
        _fail "T-E6.1" "rc=$rc after $((SECONDS - t0))s (pristine: killed by the 10s outer guard)"
    fi
}
# T-E6.2 — the backend arms signal.alarm(DEX_TIMEOUT_S+1) (belt and braces when `timeout` is absent).
test_e6_2() {
    grep -q "signal.alarm(int(os.environ.get('DEX_TIMEOUT_S'" "$REPO_ROOT/modules/dex.sh" \
        && _pass "T-E6.2 backend arms SIGALRM from DEX_TIMEOUT_S" || _fail "T-E6.2" "no signal.alarm in backend"
}
```

Mutation (PRINCIPLES #4): drop `timeout --foreground "$DEX_TIMEOUT_S"` from `_dex_run` → T-E6.1 red (outer guard fires at 10 s, elapsed > 3). Drop the `signal.alarm` line → T-E6.2 red. Also run `python3 tests/test_dex_struct.py` ([E1]) — the heredoc extraction must still work after this edit.
