## Summary
`_detect_via_drm` (`modules/dock_detection.sh:85-90`) decides "docked/handheld" from the per-connector `status` file alone — anything but the literal `connected`, including a failed `cat`, counts as "not connected" — and both watch loops (`modules/dock_detection.sh:242-252` inotify, `:255-264` poll) emit `DISPLAY_MODE_CHANGE` after a single differing read. The orchestrator's `handheld` handler (`modules/orchestrator.sh:660-685`) then runs `teardown_instance` on every slot but 1. This is exactly the HW-2 (2026-07-22) chain: one spurious `card0-DP-1/status = disconnected` read → three players torn down, MC moved to the internal panel, freeze, force reboot (#133 → #134 → #135). The #138 N-reads debounce was reverted (measured +3.9 s on every real undock: the Deck has no inotify-tools, so it polls every 3 s) and #133 was closed `not_planned`, yet `docs/PRINCIPLES.md:82-83` still says dock_detection "(post-#133 design) confirms a mode across reads" — the doc describes a design that is not shipped, and reviewers read the doc. The #133 close-out captured the real signature: a genuine undock flips `status`, `enabled` and `dpms` **together** (`disconnected/disabled/Off`); a blip on a live scanout leaves `enabled=enabled` / `dpms=On`. That corroboration is the fail-open fix (PRINCIPLES #5) and costs zero latency.

## Evidence
`modules/dock_detection.sh:84-90` — status-only verdict, read failure == "not connected":
```bash
        local status
        status=$(cat "$status_file" 2>/dev/null || true)
        status="${status//[$'\n\r']/}"

        if [[ "$status" != "connected" ]]; then
            continue
        fi
```
`modules/dock_detection.sh:244-251` — emit on one read (poll path `:256-263` is identical):
```bash
            sleep 0.5
            local new_mode
            new_mode=$(get_display_mode)
            if [[ "$new_mode" != "$current_mode" ]]; then
                echo "[dock_detection] Display mode changed: $current_mode → $new_mode" >&2
                echo "DISPLAY_MODE_CHANGE $new_mode" >> "$fifo" || true  # H6: tolerate broken pipe
```
`modules/orchestrator.sh:670-675` — the destructive consumer:
```bash
                    for _s in $active_slots; do
                        if [[ "$_s" != "1" ]]; then
                            echo "[orchestrator] Teardown slot $_s (docked→handheld transition)" >&2
                            teardown_instance "$_s" 2>&1 | sed 's/^/[orchestrator] /' >&2 || true
```
`docs/PRINCIPLES.md:82-83`: "`dock_detection` defaults to handheld and (post-#133 design) confirms a mode across reads" — no such code exists (`grep -n CONFIRM modules/dock_detection.sh` → nothing).
Reproduction (from #133, crash bundle `splitscreen-debug-20260722-184954.log` ~line 15985): DP-1 read `connected` immediately before and after the single `disconnected` sample; #133's 2026-07-25 close-out recorded the atomic three-attribute flip on a real undock.

## Failure scenario
Docked 4-up session on the projector. One transient `status=disconnected` sample (DP flicker, a busy moment, or simply a failed sysfs read: `cat` error → empty string → "not connected" on **every** connector) → `get_display_mode` says `handheld` → `DISPLAY_MODE_CHANGE handheld` → slots 2-4 torn down, slot 1 reflowed to the eDP panel → MC freezes on the internal panel → the later `docked` event is a no-op (#134) → teardown wedges (#135) → force reboot. Three players lose their session to a reading the code itself could have recognised as impossible (`enabled=enabled`, `dpms=On` on the "disconnected" connector).

## Suggested fix
Corroborate, don't wait (the #133 close-out's own recommendation). `_detect_via_drm` returns a new code `2` ("inconclusive") when no non-eDP connector reads `connected` but at least one still reads `enabled=enabled` or `dpms=On` (or its `status` could not be read at all); `get_display_mode` takes an optional `last_good` and answers with it on `2`; both watch loops pass `$current_mode`. A real undock (all three flip) is still conclusive on the first read — no added latency. `docs/PRINCIPLES.md` #5 is corrected to describe what ships and why #138 was reverted.

## Hardware verification
Hardware is the important part here: the unit suite proves the logic, not that a live 4-up survives. Mode: **Game Mode, docked** (official dock + external display), **4 pads**, `MCSS_CONTROLLER_PROXY` at its default. The Deck has no inotify-tools, so expect `[dock_detection] inotifywait not available, polling every 3s` in the log — every check below has a ≤3.5 s latency floor.
1. Baseline: `bash tests/hardware/run_all.sh stage3` through D3.6 (4-player quad) — or the RUNBOOK-HW2-TEST-HARNESS Part 2 flow — then keep the session running for a 10-minute soak. `grep -c 'DISPLAY_MODE_CHANGE' /tmp/splitscreen-debug-latest.log` must stay `0` for the whole soak.
2. **Cable wiggle / brief unplug-replug** of the DP/HDMI cable at the dock (<1 s, repeat 5×, 30 s apart) with all 4 instances live. Two acceptable outcomes, both logged:
   - the flicker never reaches `status=disconnected` (most likely, per #133's 10 ms probe) → nothing logged, session untouched; or
   - the kernel does flip `status` while the compositor keeps scanning out → the log must show, in order: `[dock_detection] Connector card0-DP-1: status='disconnected' but still enabled/On — inconclusive (status blip?)`, `[dock_detection] No connected non-eDP connector, but card0-DP-1 still looks live → inconclusive (fail-open: keep last-good)`, `[dock_detection] DRM scan inconclusive — keeping last-good mode: docked`, and **no** `[orchestrator] DISPLAY_MODE_CHANGE → handheld` / `Teardown slot` lines. All four instances still on the external display, all four pads still controlling.
3. **Synthetic blip against the real launch** (the physical flicker is not reliably reproducible — #133 could not): before launch, mirror the live tree, `mkdir -p /tmp/fakedrm && for c in /sys/class/drm/card*-*/; do d=/tmp/fakedrm/$(basename "$c"); mkdir -p "$d"; for f in status enabled dpms; do cp "$c$f" "$d/" 2>/dev/null; done; done`, launch with `DOCK_DETECTION_DRM_PATH=/tmp/fakedrm %command%` in the Steam launch options, bring up 4 players, then from Desktop-mode SSH: `echo disconnected > /tmp/fakedrm/card0-DP-1/status; sleep 8; echo connected > /tmp/fakedrm/card0-DP-1/status`. Expect the three `inconclusive` lines above within 3.5 s and zero teardown; the session must be playable throughout.
4. **Real undock still switches**: with the same session, pull the Deck off the dock (or `for f in status:disconnected enabled:disabled dpms:Off; do echo ${f#*:} > /tmp/fakedrm/card0-DP-1/${f%%:*}; done` in the synthetic setup).
