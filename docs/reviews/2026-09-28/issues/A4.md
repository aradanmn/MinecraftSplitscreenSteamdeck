## Summary
`handheld_flow`'s event loop is `_handle_msg "$msg" || break` (`modules/orchestrator.sh:774`). `_handle_msg` returns 1 for `DISPLAY_MODE_CHANGE handheld` (`:685`, "so the caller can re-enter handheld_flow") — but when the caller *is* handheld_flow, `break` falls through to `cleanup` (`:778`) → `teardown_all_instances` → slot 1 killed → `main()` returns → the session is over. A display blip escalating to teardown is exactly the class PRINCIPLES #5 forbids (and the class #133/#138 tried to debounce away at the detector instead of at the consumer).

## Evidence
```bash
# modules/orchestrator.sh:771-778 (handheld_flow)
if msg=$(_read_fifo_msg "$ORCHESTRATOR_FIFO_READ_TIMEOUT_S"); then
    echo "[orchestrator] FIFO message: $msg" >&2
    _handle_msg "$msg" || break          # 1 == "re-enter handheld" → break → cleanup
fi
…
cleanup
# modules/orchestrator.sh:661-686 (_handle_msg, handheld arm)
handheld)
    … teardown slots != 1 … _set_mode "handheld" … _reflow_layout
    # Return 1 so the caller can re-enter handheld_flow
    return 1
```
`DISPLAY_MODE_CHANGE docked` in handheld_flow only does `_set_mode "docked"` (`:657-660`) and keeps looping, so the docked→handheld message IS reachable from handheld_flow. Reproduced by the test below: on the original tree `cleanup` ran ~1 s after the message (`ended_early=1`).

## Failure scenario
Player is in handheld_flow (launched undocked). They set the Deck in the dock for a moment (→ `DISPLAY_MODE_CHANGE docked`, ignored) and pull it out (→ `DISPLAY_MODE_CHANGE handheld`) → the running single-player game is torn down and gamescope returns to Steam. Same outcome after an A3 re-entry with two dock monitors: the first further mode flip ends the session. With dock detection's own flap (#133/#138 history) this needs no operator action at all.

## Suggested fix
Treat `_handle_msg`'s code 1 as a no-op inside handheld_flow (the handler already did the right thing: tore down nothing, set the mode, reflowed slot 1).

Why this is correct: code 1 means "the session should now be in handheld_flow" and it already is; `continue` keeps the loop, the state file and the monitors exactly as they are. It deliberately does NOT change `_handle_msg`'s return-code contract or `docked_flow`/`main()` (A6 introduces a distinct code 2 for handheld→docked and generalizes this loop; A24 covers the overloaded code 1 in docked_flow). **Fuller fix:** a named constant for "switch to handheld" instead of the magic 1 (part of A6's diff).

## Tests
`T6.11 — handheld_flow ignores DISPLAY_MODE_CHANGE handheld and only ends on SLOT_DIED 1` (in the diff): runs `handheld_flow` with slot 1 active, writes `DISPLAY_MODE_CHANGE handheld` to the FIFO, waits > 2 FIFO read timeouts and asserts the flow is still alive and `teardown_all_instances` (sentinel) has NOT run; then writes `SLOT_DIED 1` and asserts a clean exit 0 with cleanup run. Mutation that must turn it red (PRINCIPLES #4): restore `_handle_msg "$msg" || break` — verified on the original tree.

## Hardware verification
Game Mode, handheld (undocked), 0 external pads — stage2 setup. (1) Launch, get into a world. (2) Set the Deck in the dock for ~3 s (external display connects), pull it out. Expect the game to keep running on the built-in panel. Proof: `grep -E 'DISPLAY_MODE_CHANGE|already in handheld flow|cleanup\(\) starting' /tmp/splitscreen-debug-latest.log` shows the two mode changes, `already in handheld flow — continuing`, and NO `cleanup() starting` until you quit. Before the fix the log shows `cleanup() starting` right after `DISPLAY_MODE_CHANGE → handheld` and Steam returns to the library. (Once A6 lands, step 2's dock-in switches to docked_flow and the pull-out re-enters handheld_flow — the game must still survive; re-run this step then.) `tests/hardware/run_all.sh stage2` plus this manual blip; add it as a stage2 step.
