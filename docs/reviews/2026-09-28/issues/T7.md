## Summary

`tests/test_preflight.sh:63-74` (`_mock_cleanup`) says "Reap only what the mocks started, by PID (PRINCIPLES #7)" and loops over `"$MOCKBIN"/*.pid` — but the mock body (`:45-53`) only ever writes `.args`, `.env`, `.started`. The loop is dead code, so every `kdialog`/`zenity` mock (`sleep 30`) started by T1.3, T2.1-T2.4, T3.1, T3.3, T3.4 outlives its test and the `rm -rf "$MOCKBIN"` that follows. T3.2/T3.3 (`:198,218`) then locate the mock with `pgrep -f "$MOCKBIN/kdialog"` — a name-matched lookup that exists only because the PID was never captured. CI does not hang only because `mcss_notify_user` (`modules/preflight.sh:79-90`) redirects the notifier's stdout itself.

## Evidence

```bash
# tests/test_preflight.sh:45-53 — the mock: no .pid is ever written
#!/bin/bash
printf '%s\n' "\$@" > "$MOCKBIN/$tool.args"
{ ... } > "$MOCKBIN/$tool.env"
echo running > "$MOCKBIN/$tool.started"
sleep 30
# tests/test_preflight.sh:66-70 — the reaper: iterates files that never exist
    for f in "$MOCKBIN"/*.pid; do
        [[ -f "$f" ]] || continue
```

Measured in a scratch clone (count of live `sleep 30` processes before/after one run of the pristine suite): `before=2 after=8` → six orphaned mocks per run, still alive 30 s after the suite exited.

## Failure scenario

Leaked mocks from earlier cases outlive their `MOCKBIN`; if `mktemp -d` ever reuses a name, T2.3's `zenity.started`/`kdialog.started` assertions read a previous case's files. The suite's own "PRINCIPLES #7, by PID" claim is false, and the `pgrep -f` lookups in T3.2/T3.3 are the pattern the repo has banned elsewhere. Mutation: make `mcss_notify_user` synchronous (drop the `&`) → T3.1 still passes only by elapsed time, T3.2's self-dismiss check is then testing a process it found by name.

## Suggested fix

Have the mock record its own pid and then `exec` the sleep, so the recorded pid IS the sleeping process (a plain `sleep 30` child would be orphaned by a pid-kill of the bash parent). `_mock_cleanup` then works as written; T3.2/T3.3 read the pid from the file (bounded wait, 2 s) instead of `pgrep -f`; a new T3.5 asserts that cleanup actually reaps.
