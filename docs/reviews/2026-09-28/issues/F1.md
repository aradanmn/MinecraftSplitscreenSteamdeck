## Summary
`uninstall-minecraft-splitscreen.sh:63` defines `PRISM_DIR="${PRISM_DIR:-$HOME/.local/share/PrismLauncher}"` and `:66-74` places it whole in `FULL_TARGETS`, so every full and `--purge` uninstall does `rm -rf "$HOME/.local/share/PrismLauncher"` (`:280`, via the loop at `:295-297`). Nothing in this project ever writes there: the installer deploys only under `TARGET_DIR=$HOME/.local/share/PolyMC` (`launcher_setup.sh`, `runtime_deploy.sh`, `java_management.sh`, `evsieve_management.sh`), and `PrismLauncher` appears in the code base only as a launcher-root *probe fallback* (`modules/runtime_context.sh:271`, `modules/utilities.sh:66`). Prism is the most common third-party launcher on the Deck, so this directory usually holds the user's own instances and worlds. The same file applies the "remove only what you created" rule (PRINCIPLES #7) to the podman store at `:305-311` but not here.

## Evidence
```bash
# uninstall-minecraft-splitscreen.sh:62-74
TARGET_DIR="${TARGET_DIR:-$HOME/.local/share/PolyMC}"
PRISM_DIR="${PRISM_DIR:-$HOME/.local/share/PrismLauncher}"
DESKTOP_BASENAME="MinecraftSplitscreen.desktop"

FULL_TARGETS=(
    "$TARGET_DIR"
    "$PRISM_DIR"
    ...
)
# :295-297
    for path in "${FULL_TARGETS[@]}"; do
        remove_path "$path"      # -> rm -rf "$path" at :280
    done
```
`grep -rn PrismLauncher modules/ install-minecraft-splitscreen.sh minecraftSplitscreen.sh` finds only read-side probes; no writer. Reproduced with the unit test below: on the pristine script a fake `$HOME` with a user-owned Prism world loses it on `--purge --yes` and on a full uninstall answered `n`/`y`.

## Failure scenario
A Deck user has their own PrismLauncher install with worlds, plus Minecraft Splitscreen. They run `./uninstall-minecraft-splitscreen.sh --yes` (or `--purge --yes`, or answer `n` then `y`). `~/.local/share/PrismLauncher` and every world in it is deleted. With `--yes` there is no confirmation; the target list is printed but not waited on.

## Suggested fix
Drop `$PRISM_DIR` from `FULL_TARGETS`. Support a Prism-hosted install of *ours* only when our marker (`$PRISM_DIR/minecraftSplitscreen.sh`) exists, and then remove only the artefacts this project deploys, never the root.

## Hardware verification
CI + unit test cover the logic. A two-minute Desktop-mode check on the Deck closes it: `mkdir -p ~/.local/share/PrismLauncher/instances/Keep && touch ~/.local/share/PrismLauncher/instances/Keep/level.dat`, then `./uninstall-minecraft-splitscreen.sh --dry-run --purge --yes` — the printed `Targets:` list must not contain `~/.local/share/PrismLauncher`; then a real `--purge --yes` followed by `ls ~/.local/share/PrismLauncher/instances/Keep/level.dat` (must exist). Reinstall afterwards via `tests/hardware/stage0b_install.sh`.
