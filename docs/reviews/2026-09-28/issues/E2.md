## Summary

`apply_layout` (`modules/window_manager.sh:285-397`) calls `_position_slot` as a bare statement at `:360` and again in the re-assert loop at `:383`; `_position_slot` legitimately returns 1 (no wid or pid, empty dex readback, `kwin_place_windows` failed). `dex_list_windows 2>/dev/null | while read …` at `:317-319` is a bare pipeline under `pipefail`, `kwin_place_windows` at `:198` is bare, and the geom-cache write `printf '%s' "$_sig" > "$_gf"` at `:361` is a bare redirection. Every module runs `set -euo pipefail`, `spawn_instance` calls `sync_apply_layout` bare (`modules/instance_lifecycle.sh:1138`), and the orchestrator runs `spawn_instance … >"$_si_log" 2>&1` bare inside a backgrounded `{ … } &` (`modules/orchestrator.sh:456`). The first failing `_position_slot` therefore terminates the whole spawn group: no map-keeper, no post-spawn reflow, no slot release, and the spawn log is deleted by the group's EXIT trap before it is ever echoed. Companion issue: [E3] makes the function's return status real; this issue only makes it survive.

## Evidence

`modules/window_manager.sh:360-361` and `:383` (pristine):

```bash
        _position_slot "$slot" "$x" "$y" "$w" "$h"
        mkdir -p "$_gd" 2>/dev/null; printf '%s' "$_sig" > "$_gf" 2>/dev/null
…
            _position_slot "$slot" "$x" "$y" "$w" "$h"
```

`modules/orchestrator.sh:455-462` — the `_si_rc=$?` line and everything after it is unreachable when `spawn_instance` fails:

```bash
            spawn_instance "$_slot" "$_en" "$_jn" "${_mask_pairs[@]}" >"$_si_log" 2>&1
            _si_rc=$?
            sed 's/^/[orchestrator] /' < "$_si_log" >&2
```

Minimal reproduction (same shapes, `set -euo pipefail`): a `spawn_instance` that calls an `apply_layout` whose `_position_slot` returns 1, run as `{ trap 'rm -f "$log"' EXIT; spawn_instance >"$log" 2>&1; rc=$?; …; } &` — the group prints nothing after the failing call, `rc=` never appears, and `[[ -e $log ]]` is false afterwards (trap ran, log gone).

## Failure scenario

`_poll_for_window` times out (LWJGL3 title never restored and `_NET_WM_PID` not yet set) → `window_id` empty → `_position_slot` falls to the KWin path → inside gamescope `kwin_positioner_available` fails → `return 1` → errexit. `spawn_instance` never reaches step 9 (map-keeper); the orchestrator's `_si_rc` check, "slot released" branch and `_reflow_layout` after `:456` are skipped; the EXIT trap `rm -f "$_si_log"` deletes the diagnostics for exactly this failing launch. The slot stays `active:true` with a running but unpositioned (854x480) game, and nothing retries.

Every fallible call in `apply_layout` is now status-tested: `_position_slot` failures are collected in `_failed` (and reported once at the end), the debug listing pipeline and the cache write get an intent-commented `|| true`, and `kwin_place_windows` is status-tested so `_position_slot`'s documented "return 1 on failure" is true on that path too. The geom cache is only written for a placement that succeeded (a cached signature for a failed one would make the next `apply_layout` skip the slot as "already at target") and any stale entry is removed on failure. In the orchestrator, `spawn_instance … || _si_rc=$?` makes the existing cleanup branch reachable. Note the bash rule this relies on: a function called in a `||` list runs with errexit *ignored*, so `spawn_instance`'s own explicit `return 1`s are what propagate — which is exactly what the `_si_rc` branch always assumed. Deliberately NOT changed here: `apply_layout`'s return value (E3) and the `[orchestrator] WINDOW … [kwin frameGeometry]` log tag (E24).

## Tests

Add to `tests/test_window_manager.sh` (bump `TEST_TOTAL`): a subprocess with real `set -euo pipefail`, stubbed `_position_slot`, no re-assert sleep.

```bash
# T3.10 (E2) — a failing _position_slot must not abort apply_layout under set -e:
# slot 2 is still processed and the failure summary is printed.
test_t3_10() {
    local out
    out=$(bash -c 'set -euo pipefail; export MCSS_MAX_PLAYERS=4; source "$1"
        MCSS_GEOM_DIR=$(mktemp -d); export MCSS_GEOM_DIR
        _get_wid_from_state() { echo ""; }
        _position_slot() { return 1; }
        WINDOW_MANAGER_REASSERT=0 apply_layout "1 2" 1280 800' _ \
        "$REPO_ROOT/modules/window_manager.sh" 2>&1 || true)
    if grep -q "Repositioning slot 2" <<<"$out" \
       && grep -q "positioning failed for slot(s): 1 2" <<<"$out"; then
        _pass "T3.10 — apply_layout is errexit-safe (both slots processed, failures reported)"
    else
        _fail "T3.10" "apply_layout aborted or did not report: $(tail -2 <<<"$out")"
    fi
}
```

Result: pristine → FAIL (output stops at `Repositioning slot 1 …`); patched → PASS. Mutation (PRINCIPLES #4): drop the `if _position_slot …; then … else … fi` back to a bare call and T3.10 goes red again (the subprocess dies on slot 1).

1.
