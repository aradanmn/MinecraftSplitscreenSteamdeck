## Summary

`add-to-steam.py:145-146` and `remove-from-steam.py:278-279` both do `with open(path, "wb") as f: f.write(new_data)`. `open(…, "wb")` truncates first; a crash, a SIGTERM (the installer is often run over SSH, and `system_integration.sh:291` throws the script's stderr away) or ENOSPC between the truncate and the write leaves an empty or partial `shortcuts.vdf` — the file that holds *every* non-Steam shortcut the user owns. The remover at least copies a `.mcss-backup-<ts>` first (`:275-276`); the adder's only backup is the installer's optional `tar` in `$PWD` (E18), which is skipped with a warning when it fails. STYLE-GUIDE §7.9: "atomic writes via tmp + mv".

## Evidence

```python

    new_data = data[:-2] + entry + b'\x08\x08'

```

Measured on pristine: after either script runs, `shortcuts.vdf` keeps its inode (in-place truncate+write) and the adder leaves no backup at all.

## Failure scenario

The Deck's home partition is full (common right after the Java/Minecraft downloads the same installer just did): `open("wb")` truncates to 0 bytes, `f.write` raises ENOSPC, the traceback is hidden by `2>/dev/null`, `shortcuts.vdf` is 0 bytes, and Steam starts with an empty non-Steam library. Nothing to restore from on the add side.

## Suggested fix

Write to a temp file in the same directory, `flush` + `fsync`, `os.replace` — in both scripts (one `_atomic_write`, `# PAIRED WITH`), and give the adder the remover's timestamped backup naming:

`os.replace` is atomic on the same filesystem, so the file is either the old bytes or the new bytes, never empty; ENOSPC now fails on the temp file and leaves the original untouched. The backup name matches the remover's (one convention, PRINCIPLES #9), so `tests/test_uninstall_purge.sh` T4.4's glob keeps working. Deliberately not changed: the installer's `tar` backup in `$PWD` (E18) — with a per-file backup next to the vdf it becomes redundant and can go in that item.

## Tests

New cases for `tests/test_add_to_steam.sh` / `tests/test_uninstall_purge.sh` (an atomic replace produces a NEW inode; an in-place write keeps it):

```bash
# T-E8 — both scripts replace shortcuts.vdf atomically; the adder writes a backup; no tmp left behind.
test_atomic_writes() {
    local h; h=$(mktemp -d); local cfg="$h/.steam/steam/userdata/12345678/config"
    mkdir -p "$cfg/grid" "$h/root"; : > "$h/root/minecraftSplitscreen.sh"
    printf '\x00shortcuts\x00\x08\x08' > "$cfg/shortcuts.vdf"
    local appid; appid=$(python3 -c 'import zlib,sys; print(0x80000000 | zlib.crc32(("Minecraft Splitscreen"+sys.argv[1]).encode()) & 0xFFFFFFFF)' "$h/root/minecraftSplitscreen.sh")
    local s; for s in "" p _hero _logo; do : > "$cfg/grid/${appid}${s}.png"; done; : > "$cfg/grid/${appid}_icon.ico"
    local i0 i1 i2; i0=$(stat -c %i "$cfg/shortcuts.vdf")
    HOME="$h" MCSS_TARGET_DIR="$h/root" python3 "$REPO_ROOT/add-to-steam.py" >/dev/null 2>&1
    i1=$(stat -c %i "$cfg/shortcuts.vdf")
    [[ "$i1" != "$i0" && $(ls "$cfg" | grep -c 'shortcuts.vdf.mcss-backup-') -eq 1 && $(ls "$cfg" | grep -c mcss-tmp) -eq 0 ]] \
        && _pass "T-E8a add-to-steam: os.replace + backup, no tmp" || _fail "T-E8a" "inode $i0->$i1"
    HOME="$h" python3 "$REPO_ROOT/remove-from-steam.py" --force >/dev/null 2>&1
    i2=$(stat -c %i "$cfg/shortcuts.vdf")
    [[ "$i2" != "$i1" && $(ls "$cfg" | grep -c mcss-tmp) -eq 0 ]] \
        && _pass "T-E8b remove-from-steam: os.replace, no tmp" || _fail "T-E8b" "inode $i1->$i2"
    rm -rf "$h"
}
```

Mutation (PRINCIPLES #4): put the remover back to `open(path, "wb")` → T-E8b red (`inode unchanged`) while T-E8a stays green — measured.
