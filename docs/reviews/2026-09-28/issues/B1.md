## Summary
With `MCSS_CONTROLLER_PROXY=1` (the shipped default, `modules/runtime_context.sh:210`) the `SLOT_DIED` handler in `modules/orchestrator.sh:633-640` runs `proxy_stop_slot` + `slot_free` (which writes `active:false`) and only THEN `teardown_instance`. `teardown_instance` (`modules/instance_lifecycle.sh:1200-1203`) guards on `slot_is_active`, so it returns before sending SIGTERM/SIGKILL to the bwrap process group and before its reset write at `:1250` (the only writer that nulls `pid`/`bwrap_pid`/`wid`/`js_node`). `slot_free` (`modules/slot_manager.sh:274-279`) nulls identity fields only. Result: the hung JVM the window-gone watchdog (#37 "Bug B") exists to kill is never killed, survives `cleanup()` (`teardown_all_instances` walks active slots only), and the dead window's `wid` stays in state — where the watchdog evaluates it against the slot's NEXT occupant because `spawn_instance`'s reserve write (`:1058`) does not null `wid`. Merged finding: A2. Fuller-fix note covers A22 (three encodings of "reset this slot").

## Evidence
`modules/orchestrator.sh:633-647`:
```bash

    proxy_stop_slot "$slot" 2>/dev/null || true
    slot_free "$slot" 2>/dev/null || true          # -> active:false
fi
local _td_log
_td_log=$(mktemp ...) || _td_log=""
if [[ -n "$_td_log" ]]; then
    teardown_instance "$slot" >"$_td_log" 2>&1 || true
```
`modules/instance_lifecycle.sh:1200-1203`:
```bash
if ! slot_is_active "$slot"; then
    echo "[teardown_instance] Slot $slot is not active, nothing to tear down" >&2
    return 0
fi
```
`modules/instance_lifecycle.sh:1058` (reserve write, no `wid`):
```bash
update_slot_state "$slot" "{\"active\": true, \"event_node\": \"${event_node}\", \"js_node\": \"${js_node}\", \"pid\": null, \"bwrap_pid\": null}"
```
The #174 comment above the guard (`:1181-1185`) records the symptom on a normal quit ("Slot 1 is not active, nothing to tear down") and fixed only the geom/proxy cleanups, not the skipped kill. No test can see it: `tests/test_reconnect_dispatch.sh:43` and `test_orchestrator.sh` T6.3 stub `teardown_instance`, so `test_on_slot_died_stops_and_frees` asserts call order only. Reproduced with the new tests below against the pristine tree: the tracked `setsid sleep` survives `SLOT_DIED`, `bwrap_pid`/`wid` stay populated.

## Failure scenario
1. Docked, 2+ pads. Player 2 quits in-game; the window is destroyed; the JVM hangs in shutdown (#14 / Bug B). Watchdog emits `SLOT_DIED 2`. Handler: `slot_free` -> `teardown_instance` no-ops. The 3 GiB JVM and its bwrap/PolyMC tree live on, untracked; `cleanup()` does not touch them either -> adopted by Steam's reaper -> Abort-Game overlay hang class (#135).
2. A new pad claims the freed slot 2 (`slot_claim` -> SPAWN). The reserve write leaves the dead window's `wid` in state; `bwrap_pid` is still null so the process checks are skipped, `_watchdog_window_present` returns 1 twice (window genuinely gone) -> `SLOT_DIED 2` ~4 s into the new launch -> the handler frees the slot AGAIN while the new tree keeps launching: an unmanaged instance appears on screen, not in any layout, and the slot is handed out a third time.
3. The re-spawn's `_poll_for_java` (`pgrep | head -1`, lowest pid) binds the new slot to the OLD hung JVM (B4).

## Suggested fix
Three parts, each independently sufficient for the kill (defence in depth), together also fixing the stale `wid`:
1. `orchestrator.sh` SLOT_DIED: call `teardown_instance` FIRST, then `proxy_stop_slot`/`slot_free` (both idempotent).
2. `instance_lifecycle.sh` `teardown_instance`: make the guard about processes — skip only when `bwrap_pid`, `pid` AND `wid` are all empty, so an `active:false` record that still tracks something is torn down and reset (PRINCIPLES #5).
3. `instance_lifecycle.sh` `spawn_instance`: add `"wid": null` to the reserve write so no earlier occupant's WID is ever evaluated against a new incarnation.

Why this is correct: `teardown_instance` already runs `proxy_stop_slot` and the geom-cache rm before its guard, so ordering `proxy_stop_slot`/`slot_free` after it changes nothing they do. The process-based guard keeps T4.16/T4.17 (already-inactive slot with nothing tracked -> still a no-op after the idempotent cleanups). Deliberately NOT changed: `slot_free`'s field set, the flag-off path (byte-identical), `_reap_dead_slots`, and the SIGTERM grace timing.

**Fuller fix (A22):** there are three encodings of "reset this slot" — `orchestrator.sh:465` (`_launch_slot` failure), `instance_lifecycle.sh:1250` (teardown) and `slot_manager.sh:276-278` (`slot_free`) — and none nulls every field, which is what let a live `bwrap_pid` sit on an `active:false` record. Add one `slot_reset <n>` in `instance_lifecycle.sh` that nulls the whole schema (`active pid bwrap_pid wid event_node js_node phys_uniq phys_vendor phys_product disconnected disconnected_at`) and have all three sites call it (PRINCIPLES #9); `slot_free` becomes `slot_reset`. That is a separate, mechanical change once this diff lands.

## Tests
Add to `tests/test_reconnect_dispatch.sh` (TEST_TOTAL 15 -> 18) and `tests/test_instance_lifecycle.sh` (16 -> 18); the existing `test_on_slot_died_stops_and_frees` expectation flips to `teardown:2 stop:2`:
- `test_on_slot_died_kills_real_tree` — re-sources `instance_lifecycle.sh` in a subshell (real `teardown_instance`), slot 2 `bwrap_pid` = a `setsid sleep 300` started from a throwaway subshell (own process group, not our child); `_handle_msg "SLOT_DIED 2"` -> asserts the pid is dead, `bwrap_pid` and `wid` are null. Mutation: pristine orchestrator + pristine guard -> "alive"/"13608"/"12345" (observed).
- `T4.18` — slot 2 inactive with stale `wid:77777`; `spawn_instance` with the T4.7 mocks -> `wid == null`. Mutation: drop `"wid": null` -> `wid=77777` (observed).
- `T4.19` — slot 2 `active:false` but `bwrap_pid` = live setsid'd sleep -> `teardown_instance 2` kills it and nulls `bwrap_pid`/`wid`. Mutation: restore the `slot_is_active`-only guard -> alive=1 (observed).

```bash
test_on_slot_died_kills_real_tree() {
    export MCSS_CONTROLLER_PROXY=1
    local victim
    victim=$( (setsid sleep 300 >/dev/null 2>&1 & echo $!) )      # own pgid, not our child
    local s2
    s2=$(_slot true "aa:bb" false -1 | jq -c --argjson p "$victim" '. + {bwrap_pid:$p, pid:$p, wid:12345}')
    _seed "$(jq -n --argjson s2 "$s2" '{"2":$s2}')"
    ( source "$REPO_ROOT/modules/instance_lifecycle.sh"; _handle_msg "SLOT_DIED 2" ) >/dev/null 2>&1 || true
    sleep 0.2
    local alive="dead"; kill -0 "$victim" 2>/dev/null && alive="alive"
    assert_equals "$alive" "dead" "flag on SLOT_DIED → REAL teardown_instance killed the tracked process group"
    assert_equals "$(_get_slot_field 2 bwrap_pid null)" "null" "flag on SLOT_DIED → bwrap_pid nulled"
    assert_equals "$(_get_slot_field 2 wid null)" "null" "flag on SLOT_DIED → stale wid nulled"
    kill -9 "$victim" 2>/dev/null || true
    _cleanup
}
```
