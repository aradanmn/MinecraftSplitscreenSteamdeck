## Summary
`system/deck-display-fixes/dock-display-hotplug.sh:2` says "Fired by udev on any DRM hotplug event" and ends (`:55-59`) with `su -s /bin/bash deck -c "… systemctl --user restart gamescope-session.target"`, which only works as root. `install.sh:15` merely copies it to `~/.local/bin` and installs no udev rule — no `*.rules` file exists anywhere in the repo or its history (`git log --all --diff-filter=A -- '*.rules'` is empty). After `./install.sh` nothing ever runs it. Run by hand as `deck`, `su` sits on a password prompt whose stderr is discarded — an unbounded silent wait (PRINCIPLES #6). `README.md:13` says it "restarts gamescope only if MST probe failed (EDID missing)"; the code (`:4`, and the loop's `edid_size -gt 0 → break 2 → restart`) restarts whenever a DP output presents an EDID, and on timeout. `stable` is assigned and never read (SC2034).

## Evidence
```bash
# dock-display-hotplug.sh:55-59
su -s /bin/bash deck -c \
    "XDG_RUNTIME_DIR=/run/user/1000 \
     DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus \
     systemctl --user unset-environment WAYLAND_DISPLAY DISPLAY XAUTHORITY; \
     systemctl --user restart gamescope-session.target" 2>/dev/null || true
# install.sh:15 — the only place the script is referenced
install -m 0755 "$HERE/dock-display-hotplug.sh"        "$USER_BIN/dock-display-hotplug.sh"
```
`grep -rn "dock-display-hotplug" --include='*' .` → the script itself, `install.sh`, `README.md`. No rule, no unit, no caller.

## Failure scenario
The maintainer follows the README (`cd system/deck-display-fixes && ./install.sh`), believes hotplug recovery is in place; a dock re-plug that loses EDID is never handled. Someone runs `~/.local/bin/dock-display-hotplug.sh` by hand to test it and it hangs silently for ever on the hidden `su` password prompt.

## Suggested fix
Ship the rule and have `install.sh` install it (generated with this user's `~/.local/bin`, since udev has no `$HOME`), detaching the script with `systemd-run` because udev kills long-running `RUN+=` programs and this one polls for up to 45 s. Add a root guard so a by-hand run fails loudly instead of waiting silently, drop the dead `stable` variable, and make the README row describe what the code does.

```diff
+# Installed to /etc/udev/rules.d/ by install.sh (which substitutes @USER_BIN@).
+# udev forbids long-running RUN+= programs (they are killed at the event
+# timeout), and the hotplug script polls for up to MAX_WAIT seconds, so it is
+# detached into a transient unit. The fixed --unit name doubles as a lock: a
+# second DRM event while a run is in flight is refused by systemd-run rather
+# than starting a parallel poll (the script's own cooldown stamp covers the
+# rest). --collect garbage-collects a failed unit so the name is reusable.
+ACTION=="change", SUBSYSTEM=="drm", ENV{HOTPLUG}=="1", RUN+="/usr/bin/systemd-run --no-block --collect --unit=mcss-dock-display-hotplug @USER_BIN@/dock-display-hotplug.sh"
```

Why this is correct: `ACTION=="change", SUBSYSTEM=="drm", ENV{HOTPLUG}=="1"` is the event the script's header already names; `systemd-run --no-block --collect --unit=mcss-dock-display-hotplug` runs it as root outside udev's event timeout, and the fixed unit name refuses a second concurrent run (a cheap lock on top of the script's own 60 s stamp). `install.sh` already uses `sudo` for the `/etc` sleep hook, so a second `sudo install` plus `udevadm control --reload` adds no new privilege model. Deliberately NOT changed: the restart condition itself (the README now matches it; whether "restart whenever EDID appears" is too eager is F8's territory), the hard-coded `deck`/UID 1000 (F11), and the `/tmp` stamp (F12). Alternative if the maintainer would rather not automate this: delete the script and its README row instead — but then the header's "fired by udev" claim and the `su` block go too.

Validation done: (a) `bash -n` and `shellcheck -S warning` clean on `install.sh` and `dock-display-hotplug.sh`; the rule's `sed` substitution was exercised locally and yields a single-line `RUN+="/usr/bin/systemd-run … /home/deck/.local/bin/dock-display-hotplug.sh"`; (b) `git apply --check` succeeds from the pristine repo root (adds one new file); (c) no unit suite covers `system/`; `udevadm verify` is unavailable in this environment, so the rule syntax is checked by review only — the Deck steps below are the real test.

## Tests
No CI-safe unit test is possible for a udev/root path. Add to `tests/hardware/stage3_hotplug.sh` (operator-prompted) a post-install assertion: `udevadm test --action=change /sys/class/drm/card0 2>&1 | grep -q 'mcss-dock-display-hotplug'` (proves the rule matches and names the unit) and `[ "$(id -u)" -ne 0 ] && ! ~/.local/bin/dock-display-hotplug.sh` (proves the by-hand run fails fast with the "must run as root" message). Mutation: delete the rule file → the `udevadm test` grep fails; remove the root guard → the second assertion hangs on `su` (bound it with `timeout 5`, expect 124).

## Hardware verification
Game Mode, Deck docked to a monitor over the official dock, one external pad. Run `cd system/deck-display-fixes && ./install.sh` from Desktop Mode (sudo prompts once), reboot into Game Mode, then unplug and re-plug the dock's DP/HDMI cable. Observe: `journalctl -b -u mcss-dock-display-hotplug` shows the unit starting on the plug event and `systemctl status mcss-dock-display-hotplug` shows it finished (exit 0); the external display comes back; `ls -l /tmp/gamescope-hotplug-restart-stamp` (or `/run/…` after F12) is fresh. Repeat the re-plug within 60 s and confirm no second restart (cooldown). Then run `tests/hardware/stage3_hotplug.sh` end-to-end so a splitscreen session's pad hot-plug is validated against the now-live rule (PRINCIPLES #3).
