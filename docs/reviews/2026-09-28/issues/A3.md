## Summary
On `DISPLAY_MODE_CHANGE handheld`, `docked_flow` does `return 1` immediately (`modules/orchestrator.sh:918-919`) with its controller monitor, dock monitor and watchdog still running. `main()` then calls `handheld_flow` (`:1011-1016`), which blanks `_CONTROLLER_MONITOR_PID` (`:732`) — the monitor keeps running, now untracked — and starts a SECOND dock monitor and watchdog (`:736`, `:743`), overwriting the old PIDs. `_open_fifo_reader` (`:120-124`, called again at `:722`) allocates a second fd and orphans the first. The orphaned docked controller monitor keeps emitting `CONTROLLER_ADD` into the FIFO that handheld_flow now reads, so a pad hotplug while undocked spawns a second instance — the exact "handheld bug" the `:724-731` comment says is prevented by never running the monitor in handheld mode.

## Evidence
```bash
# modules/orchestrator.sh:914-923 (docked_flow)
_handle_msg "$msg" || {
    local exit_code=$?
    …
    if (( exit_code == 1 )); then
        return 1                      # monitors still running
    fi
# modules/orchestrator.sh:732-746 (handheld_flow)
_CONTROLLER_MONITOR_PID=""            # blanks the PID of a monitor that is STILL RUNNING
if type watch_display_mode >/dev/null 2>&1; then
    watch_display_mode &              # SECOND dock monitor
    _DOCK_MONITOR_PID=$!
…
    start_watchdog &                  # SECOND watchdog
    _WATCHDOG_PID=$!
```
Reproduced by the test below on the original tree: after the hand-over all three stand-in monitors were still alive and a new FIFO fd had been allocated (`rc=1 cm=[19895] dm=[19897] wd=[19899] fd_same=no`).

## Failure scenario
Docked session, 2+ pads; the operator undocks. (1) The orphaned docked controller monitor (plus its `udevadm monitor` child) keeps running: plugging any pad while undocked → `CONTROLLER_ADD` → `slot_claim` → `SPAWN 2` → a second instance on the handheld screen. (2) Two dock monitors and two watchdogs deliver every `DISPLAY_MODE_CHANGE` / `SLOT_DIED` twice. (3) At session end `cleanup()` kills only the PIDs it still holds — the docked controller monitor and its `udevadm` survive, reparent onto Steam's reaper and keep the game "Running" (the #26/#60 symptom; the same orphaned-monitor family #135 records); the first FIFO fd is never closed.

## Suggested fix
Factor the monitor kills into one `_stop_monitors` (kills tree-first via `_kill_tree`, blanks the PID globals), call it before the `return 1` hand-over, use it from `cleanup()` (one encoding, PRINCIPLES #9), and make `_open_fifo_reader` a no-op when an fd is already held. T6.6 is updated because `cleanup()` no longer names `_WATCHDOG_PID` directly, and T6.10 is added.

Why this is correct: `_stop_monitors` is the existing `cleanup()` kill sequence (TERM tree → parent, KILL tree → parent) applied to all three PIDs; blanking the globals is what makes handheld_flow's own starts the only live monitors. The watchdog now also gets the tree kill (its only children are `sleep`s) — harmless. It deliberately does NOT change the return-code contract (A4/A6/A24 cover that), the handheld_flow start sequence, or `cleanup()`'s ordering.

Checks done: (a) `bash -n` on both patched files — OK; (b) `git apply --check` against the pristine tree — OK; (c) `tests/test_orchestrator.sh` on the patched tree — 10/10; on the original tree with the new tests, T6.6 and T6.10 fail (monitors alive, fd not reused). No new shellcheck findings in the module (two SC2030/2031 *notes* in the test about deliberate subshell assignment).

## Tests
Both are in the diff above. `T6.10 — docked_flow hand-over stops all monitors, blanks PIDs, FIFO fd reused`: real long-lived stand-ins for the three monitors record their PIDs; `DISPLAY_MODE_CHANGE handheld` is written to the FIFO; after `docked_flow` returns 1 the test asserts all three are dead, the globals are empty, and a second `_open_fifo_reader` reuses the fd. Mutation that must turn it red (PRINCIPLES #4): remove the `_stop_monitors` call before `return 1` (verified: the original tree fails with all three alive). `T6.6` now asserts `cleanup()` routes through `_stop_monitors` and that `_stop_monitors` covers `_WATCHDOG_PID`.
