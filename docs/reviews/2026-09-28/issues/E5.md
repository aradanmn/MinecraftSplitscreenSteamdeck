## Summary

`kwin_set_noborder` (`modules/kwin_positioner.sh:269-310`) validates its argument with `[[ -z "$pid" ]] && return 1` only (`:270-271`), then writes `if (!w || w.pid !== ${pid}) continue;` and `print("[kwin_noborder] pid=${pid} …")` (`:287`, `:291`) into a script that KWin executes. Its sibling `kwin_place_windows` got the H7 hardening (`:136-143`: every field must match `^[0-9]+$` "before interpolating into the JS literal"); this function did not. It also has zero callers — `grep -rn kwin_set_noborder` finds only the definition, the module header (`:17`, `:33`) and a stale comment in `minecraftSplitscreen.sh:719` claiming it is "called in spawn_instance" (spawn_instance step 7.5 actually uses `dex_set_decorations`, `modules/instance_lifecycle.sh:1129-1131`).

## Evidence

`modules/kwin_positioner.sh:269-271`, `:284-291`:

```bash
kwin_set_noborder() {
    local pid="$1"
    [[ -z "$pid" ]] && return 1
    …
    cat > "$jsfile" <<KWINJS
(function () {
    …
        if (!w || w.pid !== ${pid}) continue;
    …
    print("[kwin_noborder] pid=${pid} set noBorder on " + n + " window(s)");
})();
KWINJS
```

`pid=abc` produces `w.pid !== abc` (a bare identifier that throws inside KWin's script engine); `pid="123 456"` produces a syntax error; `pid="1;alert(1)"` is executed as two statements. With the patch, all four of `""`, `abc`, `123 456`, `1;alert(1)` are rejected before `mktemp`/`qdbus` run (verified with a stubbed `kwin_qdbus` that aborts if reached).

## Failure scenario

Today the only plausible pid source is `get_java_pid` (state JSON), so exploitation needs a poisoned state file; the realistic failure is a future caller passing an empty-after-trim or garbage value and getting a silently non-working script — the very class H7 fixed next door. Dead public API is also the kind of function that gets re-wired later without anyone re-reading it; the stale "called in spawn_instance" comment actively invites that.

The generated JS and the D-Bus sequence are unchanged for a valid pid. **Fuller fix (design decision):** delete `kwin_set_noborder` outright, Fix #90 style (zero references, decoration is handled by `dex_set_decorations`), together with its header lines and the `minecraftSplitscreen.sh:719` comment — and, if [E4]'s `_kwin_run_oneshot` refactor is done, there is then only one generator to harden. Verification done on a scratch copy: (a) `bash -n` on `modules/kwin_positioner.sh` and `minecraftSplitscreen.sh` passes; (b) `git apply --check` from the repo root against the pristine tree succeeds, also cumulatively after [E4] (the hunks are adjacent but disjoint); (c) no unit suite covers the module; the stub probe below was run (all four bad pids rejected without reaching `qdbus`).
