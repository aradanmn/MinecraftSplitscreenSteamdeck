## Summary

`hw_reap_stale_session` (`tests/hardware/lib/helpers.sh:727-729,742`) runs four unconditional name-matched `pkill -9 -f` sweeps on every stage launch and stop (`helpers.sh:817` `hw_launch_orchestrator`, `helpers.sh:851` `hw_stop_orchestrator`). PRINCIPLES #7 bans exactly this. The `kwin_wayland` line is justified by "kwin_wayland only ever runs as this project's OWN nested session" — false in SteamOS Desktop Mode and on every Bazzite/Plasma-Wayland host the repo now supports (#198/#199), where `kwin_wayland` is the operator's whole desktop. `-f 'latestUpdate'` matches any process whose *command line* contains that substring (an editor, an SSH `tail -f .../latestUpdate-1/latest.log`, `tests/benchmark/sampler.sh`, the very shell that launched the suite).

## Evidence

```bash
# tests/hardware/lib/helpers.sh:725-742
    # Stale Steam reaper for our shortcut: while it lives, Steam thinks the game
    # is still running and steam://rungameid/ won't relaunch it.
    pkill -9 -f 'SteamLaunch.*minecraftSplitscreen' 2>/dev/null || true
    pkill -9 -f 'latestUpdate' 2>/dev/null || true
    pkill -9 -f 'bwrap.*PolyMC' 2>/dev/null || true
    # kwin_wayland unconditionally, NOT marker-gated ...
    pkill -9 -f 'kwin_wayland' 2>/dev/null || true
```

Reproduced in a scratch clone with a fake operator process whose argv is `tail -f .../latestUpdate-1/.minecraft/logs/latest.log` (a renamed `sleep`), then calling the pristine helper:

```
-- pristine helper:
  operator's 'tail -f …latestUpdate-1/latest.log' (pid 6347) was SIGKILLed by pkill -9 -f latestUpdate
-- patched helper:
  operator's 'tail -f …latestUpdate-1…' survived
```

(A first attempt at that probe SIGKILLed the shell running it, because that shell's own command line contained the string `latestUpdate`.)

The marker-scoped alternative already exists in the same function (`helpers.sh:721-724`) and in the launcher's own guards (`minecraftSplitscreen.sh` `_mcss_nested_pids` / `_mcss_own_run_pids`, #58/#60): a process is ours iff its environ carries `SPLITSCREEN_DEBUG_LOG=`. The one real gap the `kwin_wayland` pkill papered over is that `kwin_wayland`'s own environ never carries the marker (its parent `kwin_wayland_wrapper` does) — an ancestry check closes it without name matching.

## Failure scenario

Operator runs `bash tests/hardware/run_all.sh stage3` from a Bazzite desktop or SteamOS Desktop Mode → `pkill -9 -f kwin_wayland` SIGKILLs the compositor → the whole graphical session dies, including the Konsole running the suite. Or: a second SSH window tailing an instance log is killed mid-run and the operator loses their diagnostics.

## Suggested fix

Replace the four `pkill` lines with one PID-scoped sweep: marked processes, their descendants (covers `kwin_wayland`, `bwrap→PolyMC→java`, `Xwayland`, `udevadm monitor`, `inotifywait`), and the Steam reaper identified as the *parent of a marked launcher* (covers the "Steam still thinks the game is running" case, and an orphaned kwin the reaper adopted). The existing marked `pgrep -f minecraftSplitscreen` loop (actors first) is kept.

What it deliberately does NOT change: the state-file reset, the marked actors-first loop, SIGKILL semantics, or the 5-sweep bound. Leftovers from a run whose reaper has already exited *and* whose own marker is absent (an orphaned kwin whose wrapper and reaper are both gone) are not reaped — the same accepted edge the launcher documents for `_mcss_nested_pids` ("a manual reap/reboot covers the upgrade edge"); the launcher's own STARTUP GUARD handles marked leftovers at the next launch anyway.

## Tests

Add `tests/test_hw_helpers_reap.sh` (CI-safe, no hardware): build the fake tree above (the probe script is short — `bash -c 'exec -a "reaper SteamLaunch AppId=1 -- /x/minecraftSplitscreen.sh" bash -c "env -u SPLITSCREEN_DEBUG_LOG sleep 300 & SPLITSCREEN_DEBUG_LOG=/tmp/x bash -c \"env -u SPLITSCREEN_DEBUG_LOG sleep 300 & sleep 300 & wait\" & wait"' &`), source `helpers.sh` with `HW_LOG=/dev/null`, assert `_hw_session_pids` equals `pstree -p $REAPER`'s PID set, excludes an unrelated `sleep`, excludes `$$`; then call `hw_reap_stale_session` with `SPLITSCREEN_STATE` unset and assert the tree is gone and the unrelated sleep is alive. Second case: a renamed-sleep whose argv contains `latestUpdate` survives the reap. Also `grep -c 'pkill' tests/hardware/lib/helpers.sh` must be 0 (structural guard).

Mutations that must go red (PRINCIPLES #4): re-add `pkill -9 -f 'latestUpdate'` → the tailer case fails and the grep guard fails; drop step 3 (descendants) in `_hw_session_pids` → the unmarked grandchild is missing from the set; drop the `_chain` exclusion → `$$` appears in the set.

## Hardware verification

1. **Desktop Mode (SteamOS) or Bazzite desktop, 0 pads needed.** Open two Konsoles; in the second run `tail -f ~/.local/share/PolyMC/instances/latestUpdate-1/.minecraft/logs/latest.log`. In the first run `bash tests/hardware/run_all.sh stage0` then `stage1` (both call the helpers; stage1's module smoke also sources the modules). Expected: the desktop session stays up, the `tail -f` is still running afterwards. Before the fix this kills the compositor.
2. **Game Mode docked, 2 pads.** Run `bash tests/hardware/run_all.sh stage2` twice back-to-back (the stale-session case the function exists for), then `stage6`. Expected: second launch renders on the TV (no black screen), and after stage6 `pgrep -a kwin_wayland` prints nothing and Steam shows the library (reaper released). In `.workdir/hardware/splitscreen-hwtest-*.log` expect `hw_reap_stale_session: state file reset to all-inactive` and NO `session PIDs still present after 5 sweeps`.
3. Stages: stage2_handheld, stage3_hotplug, stage6_teardown (`tests/hardware/run_all.sh`).
