## Summary
`mcss_stamp_apply` (`modules/version_stamp.sh:68-76`) builds three `sed s///` expressions by string interpolation. #170 sets `commit="ref:${REPO_REF}"` for curl|bash installs (`modules/version_stamp.sh:147-148`, producer `modules/runtime_deploy.sh:95-96`), and the installer's own documented usage is `REPO_REF=feat/gamescope-windowing ./install-minecraft-splitscreen.sh` (`install-minecraft-splitscreen.sh:105-107`). The `/` terminates the `s` command, sed exits 1, and the deployed launcher keeps its placeholders — reporting `dev/unknown`, the exact outcome #170 set out to fix — with only a warning. `&` in any value re-inserts the match and `\` sequences are interpreted, so `a&b` becomes `a__MCSS_COMMIT__b`.

## Evidence
```bash
# version_stamp.sh:71-75
sed -i \
    -e "s/__MCSS_VERSION__/${version}/" \
    -e "s/__MCSS_COMMIT__/${commit}/" \
    -e "s|__MCSS_BUILD_DATE__|${date}|" \
    "$file" 2>/dev/null
```
New tests against the ORIGINAL module:
```
[FAIL] T1.7 a commit containing slashes still stamps (rc=1) — expected 'MCSS_COMMIT="ref:feat/gamescope-windowing"', got 'MCSS_COMMIT="__MCSS_COMMIT__"'
[FAIL] T1.8 & \ | are literal in stamped values — got all three placeholders untouched
```
`tests/test_version_stamp.sh` (18/18 green today) did not catch this: its resolve fixture uses a ref without `/`.

## Failure scenario
Every curl|bash install from a branch ref containing `/` — all `feat/`, `fix/`, `refactor/` branches — stamps nothing; the launcher's `--version` and the debug log header say `dev/unknown`, so a bug report from a branch install cannot be tied to a commit.

## Suggested fix
```diff

```
Sed is removed rather than escaped: an escaping table (`/`, `&`, `\`, `|`, newline) is one more thing to keep correct, whereas a quoted bash replacement is literal by definition (the quotes matter — bash 5.2 enables `patsub_replacement` by default, which would otherwise make `&` special again). The `printf x`/`%x` pair preserves the file's trailing newline; `printf '%s'` writes the content back byte-exact. `mcss_stamp_normalize` and `mcss_stamp_resolve` are untouched, so `deploy.sh --check` round-trips exactly as before (T2.3/T2.4 still pass). The one semantic difference — every occurrence is replaced rather than the first per line — is a no-op on `minecraftSplitscreen.sh:52-57`, where each placeholder appears once.

## Tests
Add to `tests/test_version_stamp.sh` (TEST_TOTAL 18 → 21, run after `test_apply_silent_on_stdout`):
```bash
test_apply_handles_slash_in_commit() {   # T1.7 — the #170 ref form
    _setup; local f rc=0; f="$(_fixture_launcher)"
    mcss_stamp_apply "$f" "1.0" "ref:feat/gamescope-windowing" "now" || rc=$?
    _expect "T1.7 a commit containing slashes still stamps (rc=$rc)" \
        "$(grep -m1 '^MCSS_COMMIT=' "$f")" 'MCSS_COMMIT="ref:feat/gamescope-windowing"'
    _teardown
}
test_apply_values_are_literal() {         # T1.8 — & \ | never interpreted
    _setup; local f; f="$(_fixture_launcher)"
    mcss_stamp_apply "$f" 'v&1' 'a\\b' 'd|e'
    _expect "T1.8 & \\ | are literal in stamped values" \
        "$(grep -m1 '^MCSS_VERSION=' "$f")/$(grep -m1 '^MCSS_COMMIT=' "$f")/$(grep -m1 '^MCSS_BUILD_DATE=' "$f")" \
        'MCSS_VERSION="v&1"/MCSS_COMMIT="a\\b"/MCSS_BUILD_DATE="d|e"'
    _teardown
}
test_apply_preserves_trailing_newline() { # T1.9 — byte-exact outside the stamps
    _setup; local f before after; f="$(_fixture_launcher)"
    before="$(wc -c < "$f")"; mcss_stamp_apply "$f" "1" "2" "3"; after="$(wc -c < "$f")"
    _expect "T1.9 trailing newline preserved (size delta exact)" "$((before - after))" "47"
    _teardown
}
```
