## Summary

`tests/test_orchestrator.sh:167-172` (T6.3) drives `_handle_msg "SLOT_DIED 2"` with `teardown_instance` mocked — but not `proxy_stop_slot`/`slot_free`. Since #150 flipped `MCSS_CONTROLLER_PROXY` to default `1` (`modules/runtime_context.sh:210`), the SLOT_DIED handler (`modules/orchestrator.sh:632-634`) takes the flag-on branch and calls the real `proxy_stop_slot` (`modules/controller_proxy.sh:515-526`). The suite overrides `LAUNCHER_DIR`/`SPLITSCREEN_STATE` only, never `MCSS_HELPER_DIR`/`MCSS_PROXY_*_DIR`, so the pidfile resolves to the **production** `$XDG_RUNTIME_DIR/mcss/proxy-slot2.pid`: it identity-verifies the pid, SIGTERM/SIGKILLs it, and `rm -f`s the real `proxy-pads/slot2` and `proxy-virt/slot2` symlinks. The header's kill-safety analysis (lines 19-24) predates the flag flip and only covers `teardown_instance`.

## Evidence

```bash
proxy_stop_slot() {
    local slot="$1"
    mcss_resolve_paths
    local pid
    pid=$(_proxy_live_pid "$slot")
    [[ -n "$pid" ]] && _proxy_kill_verified "$pid" "$slot"
    _proxy_forget_slot "$slot"
    rm -f "$MCSS_PROXY_PADS_DIR/slot${slot}" "$MCSS_PROXY_VIRT_DIR/slot${slot}"
```

Reproduced by sourcing the launcher exactly as the suite does (same stubs and exports) and asking where the pidfile resolves:

```
pristine : MCSS_CONTROLLER_PROXY=1 pidfile2=/run/user/0/mcss/proxy-slot2.pid pads=/run/user/0/mcss/proxy-pads
patched  : MCSS_CONTROLLER_PROXY=1 pidfile2=<suite tmpdir>/helper/proxy-slot2.pid pads=<suite tmpdir>/helper/proxy-pads
```

T6.8's real `start_watchdog` likewise consults the real pidfiles via `_watchdog_proxy_dead` → `_proxy_tracked_pid` (harmless, but state-dependent); the same export fixes it.

## Failure scenario

Maintainer runs `bash tests/test_orchestrator.sh` on the Deck while a 4-up session is up (the header says "safe to run un-namespaced") → player 2's evsieve proxy is SIGTERM/SIGKILLed and its pad/virt symlinks deleted → P2 loses input for the rest of the session (unrecoverable per the watchdog docstring, `modules/watchdog.sh:91-98`: the sandbox is bound to the old virtual node). With no session up it still deletes any leftover symlinks under the real runtime dir.

## Suggested fix

Both belts, mirroring the existing kill-safety pattern: (1) export `MCSS_HELPER_DIR`, `MCSS_PROXY_PADS_DIR`, `MCSS_PROXY_VIRT_DIR` under `$_TMPDIR` *before* sourcing the launcher (`mcss_resolve_paths` keeps a pre-set value — `runtime_context.sh:343,358-361`), so no code path in the suite can reach the production runtime dir; (2) stub `proxy_stop_slot`/`slot_free` in T6.3, as `tests/test_reconnect_dispatch.sh:47` already does. Update the header's kill-safety note.

Why correct: T6.3's assertion is "SLOT_DIED → teardown_instance called for slot 2" — the proxy stop and identity free are peripheral to it and have their own suites (`test_controller_proxy.sh`, `test_slot_manager.sh`). It deliberately does NOT flip `MCSS_CONTROLLER_PROXY=0` for the suite: the flag-on branch is the shipped default and the handler must keep being exercised through it.

## Tests

Add to the suite header block a structural guard (or a T6.0): `[[ "$MCSS_HELPER_DIR" == "$_TMPDIR"/* ]] || { echo FATAL: helper dir is not under the suite tmpdir; exit 1; }` evaluated *after* `mcss_resolve_paths` — the same shape as the pid_max guard. Mutation (PRINCIPLES #4): delete the three `export MCSS_*` lines → guard fires (`/run/user/<uid>/mcss`), suite refuses. For the stub belt: in a scratch copy, drop the `proxy_stop_slot(){ :; }` stub *and* pre-create `$MCSS_HELPER_DIR/proxy-pads/slot2` → T6.3 removes it; with the stub the symlink survives (the tmpdir makes this harmless, which is the point of belt 1).

## Hardware verification

Deck, Desktop Mode or Game Mode docked, 2 pads (needs a live proxy for slot 2). Launch a 2-up session, confirm P2 has input, then over SSH run `bash tests/test_orchestrator.sh`. Expected: `9/9 tests passed.`, P2 still has input, `ls -l $XDG_RUNTIME_DIR/mcss/proxy-slot2.pid $XDG_RUNTIME_DIR/mcss/proxy-pads/slot2 $XDG_RUNTIME_DIR/mcss/proxy-virt/slot2` all still present, and `grep -c 'proxy_stop_slot\|_proxy_kill_verified' /tmp/splitscreen-debug-latest.log` does not increase during the run. Before the fix: P2 goes dead and the pidfile/symlinks vanish. No dedicated hardware stage; this is a "suite is safe next to a live session" check (RUNBOOK's un-namespaced-run note).
