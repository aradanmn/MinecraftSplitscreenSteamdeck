## Summary
`SPLITSCREEN_FIFO` defaults to `/tmp/minecraft-splitscreen.fifo` (`modules/runtime_context.sh:326`; the literal is re-embedded in `modules/orchestrator.sh:973-977`, A15). Every creator does `[[ -p "$fifo" ]] || mkfifo "$fifo" 2>/dev/null || true` (`orchestrator.sh:978-980`, `minecraftSplitscreen.sh:580`, `:827`, `:876`). If the path exists as a regular file/symlink/dir (a crash leftover, or any other local process — the parent is world-writable), `mkfifo` fails silently; `_open_fifo_reader` returns 1 (a warning), `_read_fifo_msg` returns 1 forever (`[[ -p ]]` fails), while the monitors happily `echo >> "$fifo"` into the regular file with no error (`controller_monitor.sh:847`, `:856`, `:926` — D11). The session runs with NO events (no hotplug, no `SLOT_DIED`, no dock changes) and no error naming the cause. A same-host user who owns the path can inject `SLOT_DIED 1` / `CONTROLLER_ADD …` lines.

## Evidence
```bash
# modules/runtime_context.sh:326
export SPLITSCREEN_FIFO="${SPLITSCREEN_FIFO:-/tmp/minecraft-splitscreen.fifo}"
# modules/orchestrator.sh:973-980 (main)
if [[ -z "$fifo" ]]; then fifo="/tmp/minecraft-splitscreen.fifo"; export SPLITSCREEN_FIFO="$fifo"; fi
if [[ ! -p "$fifo" ]]; then mkfifo "$fifo" 2>/dev/null || true; fi        # silent
# modules/controller_monitor.sh:847
echo "$_add_line" >> "$fifo"                                              # appends to a plain file, no error
```
Reproduced: T39 on the original tree runs `main()` with a directory at `SPLITSCREEN_FIFO` — the flow starts (`FLOW_RAN rc=0`), deaf; T40 shows the writer appends into a plain file.

## Failure scenario
`touch /tmp/minecraft-splitscreen.fifo` by any process (or a leftover from a killed run where the FIFO was replaced) → next launch: players already connected join at startup (the acquisition path bypasses the FIFO) but nothing reacts afterwards — no hotplug, no player-leave teardown, no dock/undock, and the session never ends on its own; the only hint is one "could not open persistent FIFO reader" warning.

## Suggested fix
Default the FIFO under `$MCSS_HELPER_DIR` (0700, per-user; the value rides `mcss_exec_env_string` so the inner handler sees the same path); add `mcss_ensure_fifo` (reuse a FIFO; create 0600; replace a regular file WE own; refuse anything else loudly) and use it at all four creators — fatal-loud in `main()` and `launchProdFromPlasma`; guard the three controller_monitor writers with a `-p` check (`_cm_fifo_write`) that logs and drops instead of writing into a plain file. `main()`'s literal goes away (A15).

Why this is correct: the hardware harness (`tests/hardware/run_all.sh`) and every unit suite set `SPLITSCREEN_FIFO` explicitly, so only the production default moves; replacing a regular file is limited to files we own (a crash leftover), everything else is refused rather than guessed. `dock_detection.sh:249` already tolerates a broken pipe (`|| true`); `_cm_fifo_write` brings the other writer in line. It deliberately does NOT change the FIFO's message format, the persistent-reader logic (#151), or the per-call fallback. **Overlap:** A12 edits the same helper-dir block in `runtime_context.sh`; apply A12 first, then this (the FIFO default must follow the helper-dir resolution either way).
