## Summary
`modules/watchdog.sh:212-226` remembers a reported death as `_WATCHDOG_REPORTED[$slot]=1` and clears it only when a poll observes `active != true`. The `SLOT_DIED` handler now completes in well under a second, and a queued `CONTROLLER_ADD` (returning pad, startup-acquire straggler) re-reserves the same slot with `active:true`; if both happen inside one `sleep "$poll_interval"` (2 s) the watchdog never sees the inactive gap and the second occupant's death is never reported. `_reap_dead_slots` only covers the process-dead case, so a hung-JVM / black-screen second occupant is never reclaimed. The window-gone debounce counter has the same blind spot: it is not reset when the slot's `wid` changes.

## Evidence
`modules/watchdog.sh:212-226`:
```bash
if $dead && [[ -z "${_WATCHDOG_REPORTED[$slot]:-}" ]]; then
    echo "SLOT_DIED $slot" >> "$fifo" || true
    _WATCHDOG_REPORTED[$slot]=1
fi
else
    # Slot is inactive — clear dedup cache so it can be monitored again on reuse
    if [[ -n "${_WATCHDOG_REPORTED[$slot]:-}" ]]; then
        unset '_WATCHDOG_REPORTED[$slot]'
    fi
```
Reproduced with T5.16 below against the pristine module: after the first `SLOT_DIED 1`, rewriting slot 1 as `active:true` with a new dead `bwrap_pid` (no `active:false` in between) produces no second `SLOT_DIED` within 3 s (`first='SLOT_DIED 1' second=''`).

## Failure scenario
Docked 4-up. Slot 2's first occupant dies -> reported -> handler frees the slot and a queued ADD re-claims it inside the same 2 s poll. The second occupant later quits (window gone) -> `dead=true` but `_WATCHDOG_REPORTED[2]` is still set -> no `SLOT_DIED`. The slot shows a black tile with a hung JVM forever; the pad cannot be re-used because the slot is still `active`.

## Suggested fix
Key the dedup on the incarnation (`bwrap_pid`, or `none` while null) rather than the slot, re-arm whenever the incarnation changes, and restart the window-gone debounce whenever the `wid` changes.

Deliberately NOT changed: poll interval, the `wp == 2` skip, the proxy check (see B12 in the low/info batch for its side effect).

## Hardware verification
Game Mode docked, 3 pads (stage3_hotplug). Launch 3-up; unplug pad 3 and IMMEDIATELY quit slot 3's game so `SLOT_DIED 3` and the re-plug `CONTROLLER_ADD` land in the same 2 s window (repeat 3-4 times — the race is timing-dependent). Then quit the re-claimed slot 3 normally. Expect in `/tmp/splitscreen-debug-latest.log` a second `[watchdog] Slot 3 … → SLOT_DIED` for the new occupant (optionally preceded by `[watchdog] Slot 3 new incarnation (bwrap_pid … → …), re-arming`) and a `[teardown_instance] Tearing down slot 3` for it. `grep -c 'SLOT_DIED 3' /tmp/splitscreen-debug-latest.log` must be 2.
