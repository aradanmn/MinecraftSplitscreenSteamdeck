## Summary

`setup_steam_integration` (`modules/system_integration.sh:143-157`) does `steam -shutdown … ; sleep 3; pkill -x "steam"; sleep 2` after a single `pgrep -x steam`, unconditionally. PRINCIPLES #7 / CLAUDE.md non-negotiable: no `pkill`/`killall`/name-matched kills. `remove-from-steam.py:20-23` and `:304-305` in the same repo say the opposite half of this "paired inverse" out loud: "Never restart Steam for the user — a remote `steam -shutdown` has wedged Game Mode before", and it refuses with exit 2 when Steam is running. And when the 10 s exit poll times out, the installer "proceed[s] anyway" (`:202-204`) — an edit Steam will silently revert on exit.

## Evidence

`modules/system_integration.sh:143-157` (pristine):

```bash
            if pgrep -x "steam" >/dev/null 2>&1; then
                steam_was_running=true
                print_progress "Shutting down Steam to safely modify shortcuts database..."
                steam -shutdown 2>/dev/null || true
                sleep "$STEAM_INTEGRATION_GRACEFUL_SHUTDOWN_WAIT_S"
                pkill -x "steam" 2>/dev/null || true
                sleep "$STEAM_INTEGRATION_FORCE_CLOSE_WAIT_S"
```

`:202-204`: `print_warning "⚠️  Steam shutdown timeout - proceeding anyway (may cause issues)"`.

## Failure scenario

Installer run from a Konsole inside Game Mode, or over SSH while the Deck sits in Game Mode: `steam -shutdown` + `pkill -x steam` take down the Steam client that owns the gamescope session — the user's session ends mid-install (the exact hardware incident the remover cites). `pkill -x steam` also matches any process whose comm is `steam`, including another user's client on a shared desktop box. And a Steam that did not exit within 10 s gets the file edited under it anyway, which it overwrites on exit — the shortcut "was added" and then is not there.

## Suggested fix

Never signal Steam. Detect (read-only), tell the user to close it, wait bounded and visibly (#6), and on timeout SKIP the Steam step with manual instructions instead of proceeding:

Detection stays the existing read-only `pgrep -x steam` + `~/.steam/steam.pid` poll (a read, not a kill — #7 bans signalling by name). The wait is bounded (60 × 1 s, named constants; the two constants that only timed the removed signals are deleted, #86 hygiene) and shows a TTY-only countdown so it is visibly "waiting for you", not hung (#6). On timeout the function returns 0 before the backup/script steps — nothing is edited under a running Steam — and prints the manual path (Games → Add a Non-Steam Game, with the `launchFromPlasma` launch option). Under `--yes`/non-interactive the behaviour is the same: wait, then skip. Fuller fix (design decision): mirror the remover's `/proc/*/comm` probe (also catches `steamwebhelper`) via a shared `_steam_client_running` helper with a `# PAIRED WITH remove-from-steam.py steam_is_running()` comment; and drop the now-redundant `$PWD` tar backup (E18) once [E8] lands.

Verification done on a scratch copy: (a) `bash -n modules/system_integration.sh` passes and `grep -n 'pkill\|steam -shutdown\|killall'` finds only comments; (b) `git apply --check` from the repo root against the pristine tree succeeds; (c) `bash tests/test_installer.sh` on a tree with the patched module: `17/17 tests passed` (T7.16 greps this function's prompt line — unchanged). Probe with a renamed `sleep` as a fake `steam` process (tracked PID, killed by PID afterwards) and the constants pre-locked to a 2 s wait: the function prints the "Steam is running" warning, then "still running - skipping the Steam shortcut", returns 0, and the fake process is still alive afterwards — the installer never signalled it.

## Tests

Add to `tests/test_installer.sh` (T7.x), mirroring `test_uninstall_purge.sh` T5.1's tracked-PID pattern:

```bash
# T7.19 (E9) — with a Steam client running, setup_steam_integration never signals it:
# it warns, waits (bounded), skips, returns 0, and the process is still alive.
test_t7_19() {
    local d; d=$(mktemp -d); cp /bin/sleep "$d/steam"; "$d/steam" 120 & local spid=$!
    local out rc=0
    out=$(HOME="$d/home" TARGET_DIR=/x timeout 20 bash -c '
        _STEAM_INTEGRATION_CONSTANTS_LOCKED=1 STEAM_INTEGRATION_SHUTDOWN_POLL_INTERVAL_S=1
        STEAM_INTEGRATION_SHUTDOWN_MAX_ATTEMPTS=2 MCSS_STEAMGRIDDB_ICON_URL=x
        source "$1"; print_header(){ :; }; print_progress(){ :; }; print_success(){ :; }
        print_info(){ echo "$*"; }; print_warning(){ echo "$*"; }
        mcss_prompt(){ local -n o="$4"; o=y; }
        setup_steam_integration; echo "rc=$?"' _ "$REPO_ROOT/modules/system_integration.sh" 2>&1) || rc=$?
    local alive=0; kill -0 "$spid" 2>/dev/null && alive=1
    kill "$spid" 2>/dev/null; wait "$spid" 2>/dev/null   # tracked PID only (PRINCIPLES #7)
    if [[ $alive == 1 ]] && grep -q "skipping the Steam shortcut" <<<"$out" && grep -q "rc=0" <<<"$out"; then
        _pass "T7.19 — Steam running: warned, skipped, never signalled"
    else
        _fail "T7.19" "alive=$alive rc=$rc: $(tail -3 <<<"$out")"
    fi
    rm -rf "$d"
}
```

Mutation (PRINCIPLES #4): restore a `pkill -x steam` (or `kill "$spid"`-equivalent) in the running branch → the fake process dies → `alive=0` → red. Restore "proceeding anyway" → no "skipping" line → red.

## Hardware verification

Stage0b_install (installer verification), two runs:

1. **Desktop Mode, Steam open.** Run the installer; at the Steam step it must say "Steam is running - it must be closed" and count down; close Steam from its menu within 60 s → "Steam closed - shortcuts database is safe to edit" → shortcut added. Restart Steam: "Minecraft Splitscreen" is in the library, every other non-Steam shortcut intact.
2. **Game Mode, installer in a Konsole (or over SSH while the Deck is in Game Mode).** Do NOT close Steam. After 60 s the installer must print "still running - skipping the Steam shortcut" plus the manual instructions and continue with the desktop entry; the Game Mode session must still be up afterwards (this is the incident scenario; before the fix the session died). `ps -o comm= -p "$(cat ~/.steam/steam.pid)"` still prints `steam`.
3. Then, in Desktop Mode with Steam closed, re-run the installer: the shortcut is added on the second pass.
