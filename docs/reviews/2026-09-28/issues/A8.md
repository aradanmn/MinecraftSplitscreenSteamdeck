## Summary
The #58/#60 process scoping keys on `SPLITSCREEN_DEBUG_LOG=` in `/proc/PID/environ` (`minecraftSplitscreen.sh:326-344`, `:359-370`). But `/proc/PID/environ` is the execve-time environment block; the launcher's `export SPLITSCREEN_DEBUG_LOG="$LOG"` at `:87` does not change it, and forked subshells inherit the unchanged block (reproduced: after `export`, `grep -c … /proc/$$/environ` is 0 for the shell and for a `( … )` subshell). So the outer `launchFromPlasma` supervisor (exec'd by Steam without the var), all of the launcher's `$(…)`/`&` subshells, and Steam's reaper are INVISIBLE to `_mcss_nested_pids`, while the comment at `:346-356` claims the sweep catches "a prior run's … supervisor, or Steam reaper" and that the evaluating subshell "can list itself" — neither is true. Separately, `_supervise_reap_nested_session` runs `systemctl --user stop plasma-workspace.target` (`:683-685`) with no scoping: a stale supervisor still in its retry loop while a NEWER session is booting stops the new session's target (the #60 overlap; the orphaned-tree family #135 records).

Sandbox: `bash -c 'export X=1; grep -zc X= /proc/$$/environ'` → 0. The test below (T-A8a) confirms the executed launcher's own environ carries no marker on the original tree (count 0) and does with the fix (count 1).

## Failure scenario
A stale outer supervisor (bounded, but up to ~8 passes + 30 s grace + 90 s boot ≈ 2+ min) survives the "stale tree" sweep of the next launch; if the new launch overlaps it, the old supervisor's unscoped target stop tears down the new session's Plasma ~25 s after boot (the #60 symptom by a second mechanism). `tests/hardware/stage6_teardown.sh`'s "no marked survivors" assertion also cannot see a leftover supervisor.

## Suggested fix
Re-exec the launcher once with the marker in its real environment (same PID — Steam's reaper is unaffected), fix the two comments to say what the marker actually covers, and skip the target stop when a marked `startplasma-wayland` from ANOTHER run is live.

Why this is correct: after the re-exec every process of the run — the supervisor itself, its forked subshells, and everything it execs — carries the marker, which is what `_mcss_nested_pids`/`_mcss_own_run_pids`/stage6 assume; `_mcss_stale_tree_pids` still excludes `$$` and the ancestor chain, so a run never sweeps itself. The autostart'd inner handler already has the var on its Exec line, so it never re-execs. The foreign-session check uses the same two helpers the reap loop already uses (`_mcss_nested_pids` minus `_mcss_own_run_pids`). It deliberately does NOT change the sweep's `kill -9`, the marker's name, or the reap loop bounds. **Fuller fix:** record the supervisor PID in a run file under `$MCSS_HELPER_DIR` and reap by PID (PRINCIPLES #7) instead of by cmdline pattern.

## Tests
T-A8a copies the launcher into a scratch tree with a stub `modules/runtime_context.sh` whose `mcss_resolve_environment` records `grep -zc SPLITSCREEN_DEBUG_LOG= /proc/$$/environ` from INSIDE the executed launcher and exits; expects 1 (mutation: drop the re-exec → 0). T-A8b stubs `systemctl` on PATH, makes `_mcss_nested_pids` report a foreign marked `startplasma-wayland` and `_mcss_own_run_pids` nothing, runs `_supervise_reap_nested_session` under `MCSS_ENV_CONTEXT=gamescope`, and asserts no `stop plasma-workspace.target` call (mutation: drop the foreign check → red). Note T-A8a writes one `/tmp/splitscreen-debug-*.log` (the launcher's unconditional log path, A21) and deletes it.

