## Summary
`handheld_flow`'s header promises "On DISPLAY_MODE_CHANGE docked, returns so the caller switches to docked_flow" (`modules/orchestrator.sh:700-701`). The code does not: the `docked)` arm of `_handle_msg` only calls `_set_mode "docked"` (`:657-660`) and returns 0, so handheld_flow keeps looping in handheld, and `main()` has no handheld→docked path at all (`:1005-1023`, one-shot `case`). This is #134 exactly ("handheld→docked transition is a no-op … MC was left stranded on the internal panel"). This issue proposes the fix for #134.

## Evidence
```bash
# modules/orchestrator.sh:656-660
case "$new_mode" in
    docked)
        echo "[orchestrator] Switching to docked mode (external display detected)" >&2
        _set_mode "docked"
        ;;                                   # returns 0 → handheld_flow keeps looping
# modules/orchestrator.sh:1006-1009
case "$display_mode" in
    handheld)
        handheld_flow                        # nothing runs after it
        ;;
```
Confirmed by the tests below on the original tree (`DISPLAY_MODE_CHANGE docked` from handheld → rc 0; `main()` flow sequence `H` only).

## Failure scenario
Start handheld, dock later (#134's HW-2 trace): the state file's `.mode` flips to docked and the screen is re-probed, but no controller monitor is ever started, so external pads never spawn players, and the single-player layout is never reflowed to the external output — the session is stranded on the internal panel until quit and relaunch.

## Suggested fix
Return a distinct code 2 ("switch to docked") from the `docked)` arm when the session is currently handheld (a dock blip while already docked stays a mode-only no-op); reflow the surviving slot 1; have `handheld_flow` stop its own dock monitor + watchdog and return 2; have `docked_flow` treat 2 as a no-op, and NOT end the session on "no controller within the acquire window" when a slot (P1) is already live; make `main()` loop on the hand-over codes (1 = go handheld, 2 = go docked) for the session's lifetime. This diff also contains A4's fix for code 1 inside handheld_flow, since both live on the same line.

Why this is correct: docked_flow is already re-enterable — `_set_mode` is idempotent, `_open_fifo_reader`'s fallback is per-call (idempotent with A3), the startup acquisition dispatches already-present pads through `slot_claim` (slot 1 is active so they land on 2..N), and the session-end latch sees slot 1 active. It deliberately does NOT rebind slot 1's input (the #79 constraint — a live bwrap sandbox cannot be rebound; P1 stays on the Deck's built-in controls, which is the right answer for handheld→docked) and does NOT touch dock detection. **Overlap:** with A3 applied, replace the inline `_DOCK_MONITOR_PID/_WATCHDOG_PID` kill loop in handheld_flow with `_stop_monitors`; A11 renames `_get_mode` → `get_mode` in the docked arm. **Fuller fix:** name the codes (`ORCHESTRATOR_RC_GO_HANDHELD=1`, `ORCHESTRATOR_RC_GO_DOCKED=2`) and give docked_flow's "FIFO unset" error its own code (A24).

Expect: log `DISPLAY_MODE_CHANGE → docked`, `handheld → docked: handing over to docked_flow (slot 1 kept)`, `Starting docked flow`, `startup-acquire → CONTROLLER_ADD …`, `CONTROLLER_ADD → SPAWN slot 2`, `Controller monitor PID … (hotplug-only)`; on the external display a 2-up layout with P1 (Deck controls) and P2 (the pad); `jq '.mode, .slots."1".active, .slots."2".active' ~/.local/share/PolyMC/splitscreen_state.json` → `docked true true`. (3) Undock: P2 torn down, P1 reflows full-screen on the panel (`Switching to handheld mode`); re-dock: back to docked_flow with P2 respawned on hotplug. (4) Dock with NO pad plugged: log must NOT show `No controller within … exiting to Steam`; P1 keeps playing. (5) Quit P1 → session ends (stage6: no survivors). `tests/hardware/run_all.sh stage3` + `stage6`.
