## Summary
`.github/workflows/ci.yml:90-101` runs each suite as `out=$(bash "$suite" 2>&1) || true` and passes when the parsed `X` of `X/Y tests passed` is `>= BASELINE[suite]`. The exit status is discarded and the total is never compared. Three concrete consequences from the review: **T23** — `tests/test_uhid_pad.sh` has `TEST_TOTAL=23` but its baseline is 18 (`:82`), so five regressions pass; **T5** — a test can record a `[FAIL]` and then `_pass` in the same body (`tests/test_watchdog.sh:334-358`, T5.7), printing `15/15` and exiting 1, and CI says `OK: 15 >= 15`; **T6** — seven CI-safe suites are not in the map at all (`test_evsieve_management.sh` — the SHA-verify guard —, `test_controlify_seed.sh`, `test_module_resource.sh`, `test_probe_proxy_repoint.sh`, `test_home_bwrap_bind.sh`, `test_kwin_wrapper.sh`, `test_notify_no_controller.sh`), three of which print `[OK] all … cases passed` instead of the standard footer, and `test_installer.sh` is informational on a rationale (network fallback) that T7.7 has since removed. The design comment at `:12-14` ("none of these scripts exit non-zero on a failed sub-test") is stale: every suite now exits non-zero on failure.

## Evidence
```bash
# .github/workflows/ci.yml:82,90-101
            [tests/test_uhid_pad.sh]=18          # suite: readonly TEST_TOTAL=23
            ...
            out=$(bash "$suite" 2>&1) || true
            ...
            if (( passed < BASELINE[$suite] )); then
```
Reproduced locally with the old gate's shell block against a mutated tree (three `test_uhid_pad.sh` assertions broken → suite prints `20/23 tests passed.`, exit 1): old gate prints `OK: 20 >= 18` and exits 0. A `_fail` injected before T5.7's `_pass` → `15/15 tests passed.`, exit 1 → old gate `OK: 15 >= 15`, exit 0.

## Failure scenario
A PR breaks BTN_MODE/hat/trigger encoding in `uhid_pad.py` → `20/23 tests passed`, exit 1 → CI green → merged. Or a change breaks evsieve archive-SHA verification → `test_evsieve_management.sh` is never run → CI green.

## Suggested fix
Replace the `unit-tests` job: run **every** `tests/test_*.sh` found by glob (a `SKIP` map for the one hardware suite), write each suite's output to a file rather than a `$(…)` capture (PRINCIPLES #8), bound each suite with `timeout`, and gate on the **exit status**. Known-red suites live in a `KNOWN_FAIL` map with the *exact* summary they must print (`test_window_manager.sh` = `7/9` until T4 is fixed); any other number fails the build. Give the three `[OK]`-style suites the standard `X/Y tests passed.` footer so the "no summary line" sanity check still holds for them. `timeout-minutes: 30` on the job (F17 covers the rest of the workflow hygiene).

Why this is correct: exit status is the drift-proof signal every suite already provides (`[[ TESTS_FAILED -eq 0 ]]` or `TESTS_PASSED == TEST_TOTAL`), so a baseline table that must be hand-bumped is no longer needed and T23-style staleness cannot recur; T5's fail-then-pass exits 1 and is caught; T6's seven suites are gated automatically by the glob. `KNOWN_FAIL` keys on the exact summary so a known-red suite that gets *worse* (`6/9`) or silently *changes shape* (`7/10`) fails too. Deliberately NOT changed: the shellcheck job, the hardware/session-only suites (still skipped), the suites' own pass/fail logic (T4's inverted window_manager tests are a separate issue; this gate only pins their current state), and `test_evsieve_management.sh`'s 2-minute `_build_isolated_base` (T23's second half — worth shortening, not required for the gate; `SUITE_TIMEOUT=600` covers it).

Validation done: (a) YAML parses (`python3 -c 'import yaml'`), the extracted `run:` block passes `bash -n`, the three suites pass `bash -n`; (b) `git apply --check` of every diff succeeds from the pristine repo root; (c) the extracted block was run locally against the full `tests/` tree with the three footers applied: 27 suites gated (26 OK, `test_window_manager.sh` KNOWN-FAIL 7/9 unchanged, `test_phase_b_lifecycle.sh` skipped), exit 0, ~5 min wall clock. Mutation runs (below) turn it red.

## Tests
This is the gate itself, so the tests are mutations of the tree run through both blocks (PRINCIPLES #4), all verified locally:
1. Break three `test_uhid_pad.sh` assertions → suite `20/23`, exit 1. Old gate: `OK: 20 >= 18`, exit 0. New gate: `::error::tests/test_uhid_pad.sh failed: exit 1, 20/23`, exit 1.
2. Inject `_fail "T5.7" "…"` before T5.7's `_pass` in `test_watchdog.sh` → suite `15/15`, exit 1. Old gate: `OK: 15 >= 15`, exit 0. New gate: `::error::… failed: exit 1, 15/15`, exit 1.
3. Make one more `test_window_manager.sh` case fail → `6/9`. New gate: `::error::… printed 6/9 but KNOWN_FAIL expects exactly 7/9`, exit 1.
4. Footer mutation: change a `test_home_bwrap_bind.sh` needle → `7/8 tests passed.`, exit 1 (was `[FAIL] 1 case(s) failed`, exit 1).
