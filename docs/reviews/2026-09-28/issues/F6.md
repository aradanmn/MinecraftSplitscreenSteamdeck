## Summary
`uninstall-minecraft-splitscreen.sh:62-63` accepts `TARGET_DIR` and `PRISM_DIR` verbatim from the environment and `:280` feeds them to `rm -rf "$path"`. Nothing checks that the value is absolute, is not `/` or `$HOME`, or looks like one of our installs. `TARGET_DIR` is a generic name — other tooling exports it, and it is the *installer's* readonly global, so a shell that sourced the installer for testing still has it set. The target list is printed before the confirmation, but `--yes` skips that prompt, so a stale export becomes an unattended `rm -rf $HOME`.

## Evidence
```bash
# uninstall-minecraft-splitscreen.sh:62-63
TARGET_DIR="${TARGET_DIR:-$HOME/.local/share/PolyMC}"
PRISM_DIR="${PRISM_DIR:-$HOME/.local/share/PrismLauncher}"
# :276-283
    if [[ -e "$path" ]]; then
        if [[ "$DRY_RUN" == true ]]; then
            print_info "[dry-run] Would remove: $path"
        else
            rm -rf "$path"
```
Reproduced by the unit test below against the pristine script in a throwaway `$HOME`: `printf 'n\n' | TARGET_DIR="$h" HOME="$h" bash uninstall… --yes` exits 0 and the whole fake home (including `instances/latestUpdate-1/world.dat`) is gone; a relative `TARGET_DIR=PolyMC` is accepted; a `TARGET_DIR=$HOME/Documents` with no install inside is removed wholesale.

## Failure scenario
`TARGET_DIR=$HOME ./uninstall-minecraft-splitscreen.sh --yes` — a typo'd relocation, or an export left over from a test harness that sourced the installer — deletes the home directory with no prompt.

## Suggested fix
Validate the shape of both roots as soon as they are set (absolute, not `/`, not `$HOME`, not an ancestor of `$HOME`), and in full/purge mode refuse to remove a `TARGET_DIR` that carries none of the markers only this project writes (`minecraftSplitscreen.sh`, `modules/`, `instances/latestUpdate-*`). `--keep-data` needs no marker: it only removes named files inside the root. Both checks run before the target list and the confirmation, so `--yes` cannot skip them. `_is_mcss_install_root` is written to be reused by F1 for the Prism root.

Why this is correct: the shape check catches the catastrophic class (`/`, `$HOME`, `/home`, relative paths) with no false positives for a relocated install on an SD card (`/run/media/…/PolyMC` passes); the marker check catches "this is a real directory but not ours" and turns it into an exit-1 message instead of a deletion. Deliberately NOT changed: the default paths, `--keep-data` semantics, `--dry-run` (which now also refuses, so the dry run predicts the real outcome), and `$HOME/.local/jdk` (F1/#41 territory).
