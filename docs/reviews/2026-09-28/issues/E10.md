## Summary

`is_ours` (`remove-from-steam.py:140-157`) promises to be "deliberately conservative … A shortcut the user made themselves … must survive", but its third rule (`:155`) is `exe_s.startswith(target_dir.rstrip("/") + "/")`. The uninstaller always passes `--target-dir "$TARGET_DIR"` (`uninstall-minecraft-splitscreen.sh:430`), and `TARGET_DIR` is the PolyMC *data root* (`$HOME/.local/share/PolyMC`, `install-minecraft-splitscreen.sh:334`) — the directory that also holds the user's `PolyMC.AppImage` (`add-to-steam.py:46` even probes for it there). Any shortcut the user made to plain PolyMC, or to anything they dropped under that dir, is removed as "ours". The fixture in `tests/test_uninstall_purge.sh` only uses foreign exes under `/usr/bin`, so T4.2 "foreign shortcuts survive" cannot catch it.

## Evidence

```python
    if LAUNCHER_BASENAME in exe_s:
        return True
    if appname.decode("utf-8", "replace") == APPNAME:
        return True
    if target_dir and exe_s.startswith(target_dir.rstrip("/") + "/"):
        return True
```

Measured: with a fixture entry `("PolyMC", "/home/deck/.local/share/PolyMC/PolyMC.AppImage")` and `--target-dir /home/deck/.local/share/PolyMC`, the pristine remover leaves `0:RetroArch 1:Heroic Games` — the PolyMC shortcut is gone (and its artwork with it).

## Failure scenario

Steam library has "PolyMC" → `/home/deck/.local/share/PolyMC/PolyMC.AppImage`. The user runs `uninstall-minecraft-splitscreen.sh` (even without `--purge`, even in the default non-purge mode that promises to keep their data) → `remove-from-steam.py --target-dir /home/deck/.local/share/PolyMC` → "removing shortcut: PolyMC (appid …)", grid art deleted, file renumbered. Unrecoverable except from the `.mcss-backup-*` copy, which the user does not know exists.

## Suggested fix

Narrow rule 3 to our launcher at that root — rules 1–2 already cover everything `add-to-steam.py` can write, so this loses nothing — and add the user's-own-PolyMC entry to the fixture with a test that passes `--target-dir`:

Aside found while running this suite from a scratch checkout under `/tmp`: `uninstall-minecraft-splitscreen.sh:444` does `[[ "$helper" == /tmp/* ]] && rm -f "$helper"` to reap a *downloaded* helper, but it matches a checkout's own `remove-from-steam.py` whenever the checkout lives under `/tmp/…` and deletes it after the first run. Use a dedicated `local downloaded=true` flag instead of a path glob (one-liner; not part of this diff, outside the reviewed files).
